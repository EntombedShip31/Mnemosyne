## 零、结论速览

**核心发现：原作里与"记忆"真正强相关的不是那些招牌大招，而是四条底层设定——残秽（痕迹可回溯）、投影咒法（预演即强制）、降灵术（遗体=可读的情报存档）、适应（挨过就免疫）。**

- 原作层面挖到 **12 条**强关联条目，其中 **3 条**是可直接落地的机制原型。
- 模组层面：**"记忆"这个字面词在 5 个 jar、12 份语言文件、约 8000 条条目里零命中**——没有任何一个技能叫记忆/忘却/回想。但 JJSK 模组实现了一套完整的**「术式 → 物品 → 写入术式槽」**三态流转，是现成的"记忆存取"工程范式，值得抄结构。
- 交叉比对现有 16 个法术后，筛出 **5 个定稿法术**（见 §六）：残迹回溯、献忆、帧缚、铭刻适应，外加用户追加的**无尽忆域**（对应五条悟无量空处）。
- ⚠️ **降灵（Epic）与忆冢（Rare）已于 09-19 取消，不做**；其余 4 条因与现有法术重叠被否决（见 §五）。

## 二、A 级：强关联（核心机制即信息的存/取/残留/过载/复制）

### 2.1 残秽｜残穢（ざんえ）　`[原作明确]`

- **机制**：术式一旦行使，术师的咒力必如足迹般留在现场；长期放置强力咒物的场所也会沉积咒力。咒力极薄，非术师无法感知，术师也须凝神细看。**追踪残秽可还原"是谁用了术式""源头咒物在哪"**，是术师搜查的基本手段。名称取自小野不由美小说《残秽》，作者本人承认。
- **关联**：**"残留咒力痕迹 = 可回溯的事件记录"**。整套设定里最契合"记忆残留"的条目，没有之一。
- 来源：`jujunavi.com/glossary-zane/`、`comicjiten.com/zane/`

### 2.2 投影咒法｜投射呪法（Projection Sorcery）　`[原作明确]`

- **持有**：禅院直毘人 / 禅院直哉
- **机制**：把 **1 秒切成 24 帧**，以施术者视野为投影视角；施术者需在**脑内预先描绘一条固定轨迹**，并在此 1 秒内执行完毕。被手掌触碰者移动时必须同样遵守 24FPS；**违反即被冻结在某一帧内 1 秒**，该帧内完全无防备，击中帧可脱出但通常重伤。预定轨迹**开始后不可修改**；若过度违背轨迹或物理法则，**施术者自身也会被冻结**。领域「时胞月宫殿」把 24FPS 规则下沉到细胞级。
- **关联**：**"先在脑内描绘 → 再强制现实执行"**，本质是预演/脚本刻印。本题材**可玩性最强**的原型。

### 2.3 降灵术｜降霊術（Séance）　`[原作明确]`

- **持有**：オガミ婆
- **机制**：用**尸体**召唤死者的**"肉体情报"或"魂の情报"**，把自身或他人变形为该人。她刻意**只取肉体情报、不取魂**，以取得其肉体能力而不复活人格。但**甚爾的肉体情报覆盖了其孙子的魂の情报**，术式暴走。
- **关联**：**"人 = 可被读取/覆写的情报存档"**。直接对应"从遗体读取记忆并具现"。

### 2.4 适应｜適応（魔虚罗）　`[原作明确]`

- **机制**：记录见过的攻击并逐渐适应，最终免疫。原作表现为"车轮转动 → 开始适应 → 已完成适应"。
- **模组实现**：`jujutsu.message.adaptation_start=开始适应` / `adaptation_complete=已完成适应`；GT2 有 `gamerule.gTMahoragaCopy=魔虚罗模仿`。
- **关联**：**"挨过一次就记住了，下次不怕"**——记忆即学习，是最朴素也最硬的记忆母题。

### 2.5 复制｜模倣 Copy（乙骨忧太 / 里香）　`[原作明确]`

- **机制**：条件**不是"看过"**，而是**里香吃掉原术者身体的一部分**；部位与分量取决于术式强度与想使用的次数。术式**存储在里香体内作为外部存储**——因为乙骨的大脑会被多术式**过载**。仅里香完全显现（**每次 5 分钟**）或领域展开时可取用。
- **模组实现**：`advancements.skill_copy.title=模仿`、`item.jujutsucraft.copied_cursed_technique=复制的咒术`；`TechniqueImitation1Procedure` 改写玩家变量 `PlayerCurseTechnique`，右键把物品内术式**写进术式槽**。
- **关联**：**外部记忆库 + 脑容量过载**，几乎就是记忆主题的原型。

### 2.6 无量空处｜無量空処（Unlimited Void）　`[原作明确]`

- **机制**：领域内"**无止境地灌入信息，使对象无法动弹**"（原文用词 endless information，未直写"大脑"）。
- **模组实现**：`UnlimitedVoidProcedure` + `entity_unlimited_void`。
- **关联**：**信息过载**。→ ⚠️ 与忆海现有「忆海」「认知崩坏」高度重叠，本轮不新增（见 §五）。

### 2.7 羂索脑移植 / 咒灵操术「涡」　`[原作明确]`

- **机制**：大脑移植进他人体内后**获得宿主的咒力、全部生得术式与记忆**；但**大脑能容纳的术式有上限（约 3~4 个），超出会过载**。「涡」可对准一级以上咒灵**抽出其生得术式，仅得一次性使用**。
- **模组实现**：JJSK 的羂索菜单 `label_hyeonjae_sulsig=你的术式` / `label_sulsig_jegeo=移除` / `label_max_technique_number=最大术式编号`，配 `EFFECT_KENJAKU_GET_TECHNIQUE` + `KENJAKU_NEEDLE_HELMET`。
- **关联**：记忆读取 + 存储上限。→ 与「记忆掠夺」重叠，但**"抽取只一次性"**这一点可用（见 §六 提案 5 备注）。

### 2.8 十种影法术 · 式神继承　`[原作明确]`

- **机制**：式神被完全破坏后**不可再召唤**，但"**留下的力量被其他式神继承**"（玉犬·浑、嵌合兽颚）。（原文只说遗留的力量被继承，**没有"残骸/素材"这一说法**。）
- **模组实现**：GT2 `advancements.*_inherited`、`effect...inhertied_shadows_effect=继承影之效果`；JJC `skill_divine_dog_totality.descr=继承了逝去孪生兄弟之力的玉犬`。
- **关联**：**死亡后残留被继承** → 启发「忆冢」。

### 2.9 奇迹｜奇跡（重面春太）　`[原作明确]`

- **机制**：日常小奇迹（如看到同数字时钟）**被从记忆中抹除后储存**；濒死时释放以改写运气。他本人**因记忆被抹除而不知道自己术式原理**。
- **关联**：**以记忆为代价换取资源**的明确机制 → 启发「献忆」。

### 2.10 咒物受肉（宿傩）　`[原作明确]`

- **机制**：死后把**咒力与魂分割进二十根手指**；受肉后保有"作为人类时的记忆"；手指未解封时只能模糊感知周边情报。
- **关联**：**咒物 = 魂与情报的容器**。→ 属物品层，本轮不做法术。

### 2.11 生得术式的"刻印"　`[原作明确]`

- **机制**：术式先天**刻在右前额叶皮层**，"随时间不断把公式刻入使用者"。反转术式可**破坏该脑区再再生**从而修复烧毁的术式。相伝术式只对"继承了刻印"的血族开放。
- **关联**：最硬的"信息物理刻写"底层设定。→ 作为流派设定的世界观背书，不单独成法术。

### 2.12 里香的储藏（模组原创）　`[模组实现]`

- JJSK `RingOkkotsuItem` + `RingOkkotsuInventoryCapability`（Forge `ItemStackHandler` 挂在物品上）+ `GUIOkkotsuRingMenu`（16 格）。
- **工程价值**：**"物品挂载 ItemStackHandler 当记忆库"**是可直接借鉴的实现范式。

## 四、可借用的工程范式（来自模组解包）

JJSK 把"记忆存取"做成了四种可复用的结构，虽然它没叫"记忆"：

1. **三态流转**：术式 → 物品（`copied_cursed_technique`）→ 右键写入术式槽。对应忆海的 **写入 → 忆格 → 释放**。
2. **外置存储库**：物品挂 `ItemStackHandler` 当 16 格容器。对应忆海的**忆格数组**，但忆海是 NBT 权威（更安全）。
3. **三操作菜单**：抽取 / 备份 / 移除。对应忆海需要的 **存 / 取 / 丢**，其中"丢"目前只有遗忘法术，缺少玩家主动的**丢弃**入口。
4. **录制-回放**：`RecorderRightclickedProcedure` 录音机 —— ⚠️ **与忆海「既视感」完全同构**，说明既视感的设计方向是对的，无需新增。

### 17 · 残迹回溯（Trace Retrograde）　Uncommon · 瞬发

- **原型**：残秽（§2.1）
- **数值**：法力 25（+2/级 → 25~33）｜冷却 12s（固定）｜半径 12 格（+1/级 → 12~16）｜回溯 30s（+5/级 → 30~50）
- **机制**：回溯该区域最近 N 秒内的三类事件——**伤害 / 施法 / 死亡**，用残影粒子重现：伤害事件画一条从攻击者指向受害者的品红轨迹，死亡事件生成靛蓝光柱。同时对**区域内最近一次伤害的施加者**施加「追迹」标记 5 秒，你对被标记目标的下一击 **+15%**（+3%/级 → 15~27%）。
- **决策点**：战斗中放换增伤；战后放能**读到已经撤离的敌人**（这是「窥忆」做不到的）。冷却 12 秒，必须挑时机。
- **与「窥忆」的区别**：窥忆 = 单体 × 即时（读一个目标当前的属性）；残迹回溯 = **区域 × 时间**（读一片地方过去发生的事）。维度不同，不重叠。
- **素材**：复用窥忆的读取粒子；标记环复用 `spellSlotMark` 的形状。
- **实现要点**：需新建**服务端事件环形缓冲**——记录 `{tick, x, y, z, sourceId, targetId, kind, amount}`，容量钳 **512 条 / 覆盖 60 秒**（超出覆盖最旧），**内存不落盘**（重启丢失可接受）。查询时线性扫 512 条，开销可忽略。⚠️ 这是基础设施，建成后走马灯/既视感可复用。

### 18 · 献忆（Oblation）　Uncommon · 瞬发

- **原型**：重面春太「奇迹」——记忆被抹除以换取资源（§2.9）
- **数值**：法力 20（+2/级 → 20~28）｜冷却 25s｜**消耗 1 个忆格**（优先临时格）
- **机制**：烧掉 1 个忆格，换 **10 秒（+1/级 → 10~14）内所有法术法力消耗降为 0**，且施法速度 **+15%**（+3/级 → 15~27%）。**没有忆格时无法施放**。
- **反噬**：自身叠加 **2 层认知过载**，持续 20s。而**自身认知过载 ≥3 层时，写入类法术写入的内容持续时间 -30%** → 献忆后 20 秒内别写入。
- **为何收益是"免法窗口"而不是回血**：回血会撞上 ISS 圣/自然学派的治疗法术，违反准入准则 ⑤；"一段时间施法不要钱"是其他九大学派给不了的东西。
- **与「千忆归一」的区别**：千忆 = 全部格换伤害（爆发）；献忆 = 单格换持续输出窗口（续航）。互补。
- **素材**：复用 `engramGain` 的环（反向播放，环数 = 失去的格数）+ 千忆归一的引爆粒子降规模。
- **实现要点**：⚠️ "法力消耗降为 0"要覆写到 ISS 的耗蓝入口，实现前先 `python tools/read_mc_source.py` 确认签名，别硬改。

### 19 · 帧缚（Framebind）　Rare · 长吟 1.5s

- **原型**：投影咒法——1 秒切 24 帧、脑内预演轨迹、违反即冻结（§2.2）
- **数值**：法力 45（+3/级 → 45~57）｜冷却 20s｜持续 5s（+1/级 → 5~9）｜违反应伤害 6（+1.5/级 → 6~12）
- **机制**：吟唱期间**记录施法者自身的移动轨迹**（每 tick 采样）。吟唱结束时对终点半径 4 格内敌人施加「帧缚」。效果期间目标**每 tick 位移不得超过 0.28 格**（≈ 疾跑上限）：
  - 遵守 → 只能慢走，等于软控；
  - 违反（疾跑、跳跃冲刺、鞘翅、末影珍珠、瞬移）→ **冻结 1 秒**。冻结期间**受到任意伤害即立即解除，且该次伤害 ×1.5**。
- **决策点（双向二选一）**：进攻方要决定**打还是不打**——不打则敌人白站 1 秒，打则立刻解冻但它吃 1.5 倍。被冻结方也在**站着挨冻**和**骗对手打你**之间选。
- **与「失忆」的区别**：失忆禁用**能力**（AI / 特殊攻击）；帧缚限制**移动方式**。不重叠。
- **素材**：目标沿路径留下 24 个半透明帧方块残影（当前位置与上一位置之间插值），违反时**全部闪红并定格**；定身表现复用 `dazeAura` 的碎屑。
- **平衡限制（必须做）**：
  - 对**玩家**目标冻结时长减半（0.5s），且同一目标 **10 秒内只能被冻结一次**；
  - **BOSS 不触发冻结**，只吃移动限制（50% 时长）——红线：BOSS 免疫"剥夺"。
- **实现要点**：定身用 `MobEffect` 挂 `MOVEMENT_SPEED` 修饰符 **×0**，**不要用 `setNoAi`**（会破坏其他系统）；上一 tick 位置存 `LivingEntity.getPersistentData()`（别存 effect 里，牛奶桶会清）；伤害 ×1.5 走 `LivingHurtEvent`，伤害必须走 `DamageSources.applyDamage`。

### 20 · 铭刻适应（Adaptation）　Rare · 瞬发

- **原型**：魔虚罗适应——挨过一次就记住，下次不怕（§2.4）
- **数值**：法力 45（+3/级 → 45~57）｜冷却 30s｜铭刻期 8s（+1/级 → 8~12）｜增益期 30s（+3/级 → 30~42）
- **机制**：施法后进入 **8 秒铭刻期**，记录自己受到的**每一次伤害的伤害类型**（按 1.20.1 `DamageType` 的 msgId 分组累加）。铭刻期结束结算：
  - 某单一类型占比 **≥60%** → 对该类型 **30% 减伤**（+5%/级 → 30~50%，专注）；
  - 否则 → 对出现过的**所有类型**各 **15% 减伤**（+2/级 → 15~23%，广谱）。
- **决策点**：铭刻期必须**主动挨打**才有效果——躲得越干净收益越低。面对单一 Boss 故意只吃它的主伤害类型换 30%；面对杂兵群尽量吃多种类型换广谱 15%。
- **与现有区别**：`memory_magic_resist` 是**全局固定**抗性乘数；铭刻适应是**自适应、按类型、必须先挨打**的限时窗口。不重叠。
- **素材**：铭刻期复用 `recordingAura`（痛忆录制时那套），结算时环收拢成一层贴身护膜。
- **实现要点（⚠️ 关键）**：抗性**不能只靠 MobEffect 表达**——牛奶桶/净化会清空全部效果，当缓存则一秒内自愈。权威数据必须写 `MnemosyneData.writableRootTag(Player)`，MobEffect 只做显示与时长同步。⚠️ `CompoundTag.getCompound` 键缺失会返回脱离的新 tag 导致静默丢弃。

### 21 · 无尽忆域（Endless Realm）　Legendary · 长吟 3.0s

> 对应五条悟「**无量空处**」——无止境地灌入信息，使对象无法动弹。**名字改为记忆相关的「无尽忆域」，素材直接搬运现有「忆海」。**

- **数值**：法力 170（+8/级 → 170~202）｜冷却 120s｜领域半径 10 格（+1/级 → 10~14）｜时长 **6s**（+1/级 → 6~10）
- **机制**：展开领域，**领域内敌人完全无法行动**——不能移动、不能攻击、不能施法、不能使用物品；同时每秒叠 **1 层认知过载**。领域期间**施法者自身也无法移动**，且无法施放其他法术。
- **⚠️ 零伤害**：这个法术**不造成任何直接伤害**。它的全部价值是"把战场按停 6~10 秒"，符合"记忆流派不做最高伤害"的红线。
- **与「忆海」的区别**（两个都是 Legendary 领域，必须区分清楚）：
  - **忆海** = 自增益（忆格 +3）+ 敌人叠层 + **结束时结算伤害**；
  - **无尽忆域** = 纯控制、零伤害、时长更短（6~10s vs 忆海 15~30s）。
- **与「遗忘诅咒」的区别**：遗忘诅咒是剥夺**能力**（AI）；无尽忆域是剥夺**一切行动**。
- **BOSS 处理**：BOSS 免疫"无法行动"，改为移动速度 **-50%** 且照常叠层。
- **素材**：**直接搬运「忆海」的领域素材**（同一套穹顶粒子 + 音效，不新增任何文件）。只把配色从忆海的「靛蓝 → 品红**向外发散**」改成「白 → 靛蓝**向内收敛**」——视觉上讲的就是"信息灌进来"而不是"记忆涌出去"。
- **实现要点**：领域时长/半径必须写成源码常量数组（⚠️ 项目教训：**领域时长必须从源码常量读，别信文档**）；叠层与「忆海」共用 `MnemosyneData` 的叠层入口。
