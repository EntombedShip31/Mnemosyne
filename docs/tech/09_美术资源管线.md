## 〇、一句话结论

**法术卷轴的图标确实是"原始图案的改色"——而且是可以精确复现的机械改色。**

实测证据：

| 贴图 | 尺寸 | 不透明像素 | alpha 掩码与底图的差异 |
|---|---|---|---|
| `scroll.png`（底图） | 16×16 | 137 | — |
| `scroll_fire.png` | 16×16 | 137 | **0** |
| `scroll_ice.png` | 16×16 | 137 | **0** |
| `scroll_lightning.png` | 16×16 | 137 | **0** |
| `scroll_holy.png` | 16×16 | 137 | **0** |
| `scroll_ender.png` | 16×16 | 137 | **0** |
| `scroll_blood.png` | 16×16 | 137 | **0** |
| `scroll_evocation.png` | 16×16 | 137 | **0** |
| `scroll_nature.png` | 16×16 | 137 | **0** |
| `scroll_eldritch.png` | 16×16 | 137 | **0** |

**10 张贴图的不透明像素数完全一致（都是 137），alpha 掩码逐像素零差异。**

进一步分析颜色：底图恰好是 **11 色**，每张学派贴图都是对这 11 色的**严格 1:1 替换**。

**所以：不需要画新图。** 用一个 60 行的 Python 脚本就能生成忆海的卷轴图标。

### 三条重要观察

**① `scroll_evocation.png` 与底图完全一致（11 个颜色全不变）。**
→ 说明 **咒法学派就是"默认学派"**，底图 = 咒法卷轴。
（这也是为什么 `models/item/example_regular_scroll.json` 这个给第三方模组用的模板指向 `item/scroll`。）

**② 官方每个学派只用一个色相。**
fire 全用橙红、ice 全用蓝、holy 全用金白、blood 全用红。
GLYPH 和 RIBBON **共用同一个色相**，只靠明度区分。

**③ nature 故意保留棕色绑带**（索引 7/8/9 不变）。
说明官方也不是机械套用，会为语义做例外（棕色绑带 = 树皮/藤蔓）。

## 三、忆海的配色方案

### 3.1 设计决策：**双色相**

忆海有**两个**主色（`#534AB7` 靛蓝 + `#D4537E` 品红）。
既然官方每个学派都只用一个色相，忆海用**两个**就是天然的差异化：

| 组 | 用哪个色相 | 语义 |
|---|---|---|
| **PAPER** | 冷调淡紫灰 | 泛黄的旧纸 → 冷紫的"记忆载体" |
| **GLYPH** | **靛蓝 `#534AB7`** | 纸上的文字 = 被书写下来的记忆 |
| **RIBBON** | **品红 `#D4537E`** | 封印的绑带 = 记忆的锁 |

**这是 10 张卷轴里唯一的双色相设计**，在物品栏里一眼可辨。

### 4.2 符文：亮度渐变映射

**实测发现**：ISS 的 `<school>_rune.png` 也是同一张底图的改色（alpha 掩码差异为 0，144 像素），
**但不是干净的色相旋转**——逐像素色相差的标准差高达 17~103 度，说明是**美术手工改色**。

原因：符文原图的**饱和度极低**（`arcane_rune.png` 饱和度中位数仅 12.3，最大 46.6）。
对低饱和图做色相偏移几乎无效——"灰"没有色相可转。

**解决方案：亮度渐变映射（gradient map）**。保留原图的明暗结构，颜色完全由自定义色阶决定。

```bash
# 三种色阶风格
python gen_scroll_texture.py --mode ramp --preset mnemosyne \
    --base "<ISS>/assets/irons_spellbooks/textures/item/arcane_rune.png" \
    --ramp indigo_magenta \
    --out ../src/main/resources/assets/mnemosyne/textures/item/memory_rune.png
```

| `--ramp` 风格 | 色阶 | 效果 |
|---|---|---|
| `indigo_magenta`（**推荐**） | 深靛 → 靛灰 → 亮靛 → 品红 → 浅品红 | 与卷轴配色一致，双色相 |
| `indigo_only` | 深靛 → 亮靛 → 近白 | 干净的单色靛蓝 |
| `magenta_only` | 深品红 → 品红 → 浅品红 | 强烈的品红 |
| `paper` | 深灰紫 → 淡紫 → 近白 | 素净 |

**实测对比**（`preview_rune_modes.png`）：`hue` 模式的结果明显发灰发脏，`ramp indigo_magenta` 干净鲜明。
**结论：符文用 `ramp` 模式，不用 `hue` 模式。**

### 4.3 其余 30 张贴图：程序绘制

`tools/gen_mnemosyne_art.py`（WS-H2 新建，2026-09-16）覆盖剩下的 30 张：
物品图标 6 / 护甲图层 2 / 方块 4 / **法术图标 18**。

```bash
python tools/gen_mnemosyne_art.py --all                                     # 生成全部 30 张
python tools/gen_mnemosyne_art.py --check                                   # 逐张校验（尺寸/非空/文件名）
python tools/gen_mnemosyne_art.py --contact-sheet docs/previews/ws_h2_contact_sheet.png --scale 8
```

三个设计要点：

| 要点 | 说明 |
|---|---|
| **角色调色板** | 图标用角色字母（`m`/`d`/`l`/`h` 主色四档，`a`/`A`/`b` 另一色相三档，`s`/`S`/`x` 石头）作画，再按 3 套方案（靛蓝 / 品红 / 痛忆深紫）解释成 RGB。改配色只改一个字典 |
| **几何 DSL** | `seg` / `ring` / `disc` / `diamond` / `shard` —— 直接对应设计文档的「碎片 + 环形」母题 |
| **自动 1px 暗描边** | `outline()` 只在"不透明像素的透明邻域"补一圈暗色。这是整批图标的**统一笔触**，16 张法术图标因此看起来是一套 |

**为什么不用 `hue` / `ramp` 模式做这 30 张**：那两种模式依赖"有一张官方底图可改色"。
法术图标是官方一张一画的独立美术（116 张各不相同，实测 16×16），没有可复用的底图；
直接复制又违反 ISS 的 All Rights Reserved。**程序绘制是唯一既原创又可复现的路。**

### 5.1 关键推论：忆海**不需要**新的墨水（ink）和升级宝珠（orb）

回忆 `05_卷轴与法术书.md` §5.2 的结论：忆海卷轴**推荐复用官方 `irons_spellbooks:scroll` 物品**，
并且**建议不做合成台**（M1~M5 阶段），卷轴只从遗迹宝箱产出。

那么：
- **墨水（ink）**：官方墨水的用途是"在卷轴合成台里造卷轴"。既然我们不做合成台，**不需要新墨水**。
  如果将来做合成台（做法 B），可以用**忆晶（`memory_crystal`）**代替墨水作为输入材料。
- **升级宝珠（orb）**：官方的 `upgrade_orb_<school>.png` 用于给护甲加属性。
  忆海如果要加，可以**复用 `upgrade_orb_evocation.png` 的图形**（因为 evocation 就是默认学派），
  或者干脆不自制 orb 物品，把属性直接写在护甲上。

**这砍掉了 2 类美术资产（约 15 张图）。**

### 5.3 ⚠️ 关于"复用官方贴图"的授权边界

和音效一样，ISS 是 **`All Rights Reserved`**。所以：

| 做法 | 合法性 |
|---|---|
| 用脚本**读**官方贴图，**按官方配色规则重新生成**我们的贴图 | ✅ 我们产出的是自己的作品 |
| 把官方 `scroll_fire.png` 直接**复制**进我们的 jar | ⚠️ **有授权风险** |
| 用官方贴图做**参考**，自己重画 | ✅ |

**所以脚本方案不只是"省事"，它还顺带解决了授权问题**——
生成出来的 `scroll_memory.png` 是我们自己的派生作品，不是官方文件的拷贝。

**方块贴图（#9~#12）建议自己画或用原版 `deepslate_bricks` 改色**（原版资源在 Modding 惯例中可自由使用）。

```json
}
```

**⚠️ 但如果我们复用官方 `irons_spellbooks:scroll` 物品（推荐方案），就不需要这个模型文件。**

此时问题是：**官方卷轴怎么根据法术学派切换贴图？**

从 `models/item/` 里每个学派一个模型（`scroll.json` / `scroll_fire.json` / …）可以推断：
官方在**客户端**根据卷轴里的 `SpellData` 动态选择模型（自定义 `BakedModel` 或
`ItemProperties` 的 `overrides`）。

**M1 阶段必须实测确认**：
1. 用 `ISpellContainer.createScrollContainer(忆海法术, level, stack)` 造一个卷轴
2. 看它在物品栏里显示什么贴图
3. 如果显示的是默认 `scroll.png`（米黄），说明官方没有为第三方学派准备 fallback

**如果官方不做 fallback，我们的对策（按优先级）**：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 注册 `ItemProperties` override** | 给官方 scroll 物品挂一个客户端 predicate，读 NBT 判断学派 | ⚠️ 需要改官方物品的模型，可能与其他模组冲突 |
| **B. 自注册卷轴物品** | `mnemosyne:memory_scroll extends Item implements IScroll` | ✅ 干净，但要自己实现 `use()`/tooltip |
| **C. 接受默认贴图** | 忆海卷轴就用米黄底图，靠法术名区分 | ⚠️ 视觉上弱，但零风险 |
| **D. 混合** | 用官方的**行为**（`IScroll` 逻辑）+ 自己的**贴图** | ✅ 见下 |

**方案 D 的细节**（推荐）：
注册 `mnemosyne:memory_scroll`，它 `implements IScroll`（空标记接口，见 `05_卷轴与法术书.md` §1.1），
内部用 `ISpellContainer` 存法术，并**复制**官方 `Scroll` 的行为（`use()` 逻辑约 30 行）。
这样贴图完全可控，且所有官方系统（合成台、卷轴袋、商人、战利品函数）都会认它。

### 6.3 护甲穿戴模型

原版护甲穿戴需要两张图层贴图：

```
textures/models/armor/mnemonic_layer_1.png   64×32   头盔/胸甲/靴子
textures/models/armor/mnemonic_layer_2.png   64×32   护腿
```

**画法**：这两张是标准的"人形 UV 展开图"，最省力的做法是：
1. 下载原版 `diamond_layer_1.png` 作为 UV 参考
2. 用脚本把它整体改色为忆海配色（色相偏移 + 饱和度调整）
3. 手动修饰细节

**可以用脚本做的部分**：

```bash
# 把原版钻石护甲改色为忆海靛蓝（近似）
python gen_scroll_texture.py --mode hue --preset mnemosyne \
    --base "<原版资源>/assets/minecraft/textures/models/armor/diamond_layer_1.png" \
    --target-hue 245 --sat-scale 0.9 --val-scale 0.95 \
    --out ../src/main/resources/assets/mnemosyne/textures/models/armor/mnemonic_layer_1.png
```

**注意**：护甲的 UV 图饱和度不低，所以 `hue` 模式在这里**比在符文上效果好得多**。
但依然建议生成后手工检查一遍接缝。

## 八、脚本设计说明（给未来的维护者）

`tools/gen_scroll_texture.py` 的三个设计要点：

### 8.1 为什么用"锚点 + 插值"而不是直接写 11 个颜色

```python
PaletteSpec(
    paper_light="#EFEDF7", paper_mid="#B7B0D4", paper_dark="#5C5480",
    glyph_light="#7A6FD6", glyph_dark="#2E2570",
    ribbon_light="#F2A6C2", ribbon_mid="#D4537E", ribbon_dark="#7C2745",
)
```

只要 **8 个锚点**，脚本按底图的**明度排序**自动展开成 11 色：

- PAPER 组 5 个索引按底图 V 值降序 → 均匀插值到 3 个锚点
- GLYPH 组 3 个索引 → 插值到 2 个锚点
- RIBBON 组 3 个索引 → 插值到 3 个锚点

**好处**：调整配色时只改 1~2 个锚点，不用手算 11 个值，也不会破坏明度关系。

### 8.2 为什么 `hue_shift` 要加 `min_sat` 阈值

```python
if s100 < min_sat:
    continue   # 近灰像素保持原样
weight = min(1.0, (s100 - min_sat) / 40.0)   # 高饱和像素权重更大
```

不加阈值的话，**高光和阴影（近灰/近白/近黑）会被染色**，导致画面变脏。
加了阈值 + 权重后，只有"有颜色的部分"被偏移，明暗结构保持干净。

### 8.3 为什么保留 `--mode hue` 即使它在符文上效果不好

因为**在护甲图层上它效果好**（护甲 UV 图饱和度不低）。
`ramp` 适合低饱和的符文，`hue` 适合中高饱和的护甲。
两个模式各有适用场景，都保留。
