### 1.4 ⚠️ 两条必须遵守的并行纪律

**① `MnemosyneMod.java` 谁都不许碰。**
A 线新建的 `ModEffects` 需要主类挂载 `DeferredRegister`，但主类是 WS-0 的文件。
→ 由**集成者**在 Phase 末尾统一加那一行（就像 WS-A / WS-B 时做的那样）。

**② `registry/ModEffects.java` 是"新建"，不是"修改"。**
`registry/**` 归 WS-A，但 WS-A 已完工且**没有**创建这个文件。
新建一个 WS-A 从未创建的文件不算违反铁律一。
**A 线建好它之后，其他线就不要再动它了。**

## 三、⭐ 本次实测的三项更正（动手前必读）

### 更正 1：WS-E **不需要 Mixin，也不需要反射**

`docs/tech/03` §7.2 写的是：

> **`goalSelector` 是 protected**，外部无法直接访问。两种途径：
> 1. Accessor Mixin（推荐）2. 反射（脆弱，不推荐）

**这是错的。** 实测（2026-09-16）：

```java
// 下面这段代码在 1.20.1 Forge 47.4.0 下【编译通过】
GoalSelector gs = mob.goalSelector;              // ✅ 可访问
GoalSelector ts = mob.targetSelector;            // ✅ 可访问
for (WrappedGoal w : gs.getAvailableGoals()) {
    Goal goal = w.getGoal();                     // ✅
    int priority = w.getPriority();              // ✅
    boolean running = w.isRunning();             // ✅
    gs.removeGoal(goal);                         // ✅
    gs.addGoal(priority, goal);                  // ✅
    w.stop();                                    // ✅
}
```

原因：**Forge 的 AccessTransformer 把 `Mob.goalSelector` / `targetSelector` 提升为 public**，
在 MCP 的 `AccessTransformer` 步骤就写进了编译期的类签名里，运行时由 Forge coremod 同样应用。

**影响**：
- §7.3 的"方案 B（Mixin 拦截 `canUse()`）"**整段作废**，不需要按生物分 P0/P1 两套方案
- 统一用"**移除 + 记录 + 到期恢复**"即可
- 省掉 Mixin 的构建配置（`mixins.json` + refmap + annotation processor）
- **WS-E 从"全项目最大技术风险"降级为"量大但直白"**

### 更正 2：漏了 **18 张法术图标**

`docs/tech/11` §四 的 WS-H 任务清单只列了 12 张贴图，**漏了法术图标**。

实测依据（`AbstractSpell` 源码逐字）：

```java
public final ResourceLocation getSpellIconResource() {
    return ResourceLocation.fromNamespaceAndPath(
            getSpellResource().getNamespace(),
            "textures/gui/spell_icons/" + getSpellName() + ".png");
}
```

ISS 自己有 **116 张**同类图标（`assets/irons_spellbooks/textures/gui/spell_icons/`），
我们**一张都没有** → 法术书里 18 个忆海法术的图标全部是缺失贴图。

**必须补**：`assets/mnemosyne/textures/gui/spell_icons/<spellId>.png` × 18。

### 更正 3：编译期依赖必须用 ISS 完整 jar（已在 Phase 2 修好）

`:api` 分类器缺 `SpellDamageSource`，任何造成伤害的法术都编译不过。
已在 `build.gradle` 改成完整 jar。**新开的工作流不要把它改回去。**

## 五·五、WS-G2 的**精确交付清单**（23 个结构模板 NBT）

WS-G1 已交付全部 worldgen JSON。`tools/check_resources.py` 的检查 5a 把
`template_pool/**` 里引用的 `location` 逐个反查磁盘，得到下面这份**逐文件清单** ——
WS-G2 照着建即可，不需要再翻 JSON 推路径。

**路径规律**：`mnemosyne:<ident>` ↔ `src/main/resources/data/mnemosyne/structures/<ident>.nbt`
（实测依据：`StructureTemplateManager` 里 `new FileToIdConverter("structures", ".nbt")`）

| 分组 | 文件（相对 `data/mnemosyne/structures/`） | 数量 |
|---|---|---|
| 入口 | `memory_ruin/ruin_main.nbt` | 1 |
| 通道 | `memory_ruin/chamber/`：`corridor` `junction` `rubble_dead_end` `sealed_wall` `cracked_wall_opening` `statue_pass` | 6 |
| 房间 | `memory_ruin/chamber/`：`bookshelf_gallery` `archive_vault` `burial_alcove` `mnemonic_core` | 4 |
| 楼梯 | `memory_ruin/stair/`：`staircase` `staircase_cracked` `staircase_collapsed` | 3 |
| 地表 | `memory_ruin/surface/`：`broken_column` `fallen_arch` `collapsed_wall` `rune_plaza` | 4 |
| 装饰 | `memory_ruin/decoration/`：`bookshelf_ruined` `decayed_pot` `memory_crystal_cluster` `broken_stele` `collapsed_pillar` | 5 |
| | **合计** | **23** |

> ⭐ **缺失 NBT 的真实失败模式（实测，2026-09-16）—— 比"存档加载不了"更阴**：
> `StructureTemplateManager.getOrCreate`（`m_230359_`）→ 资源包来源（`m_230427_`）
> → 文件不存在 → `FileNotFoundException` → `m_230372_` 返回 `Optional.empty()`，
> **`FileNotFoundException` 分支一行日志都不打**（只有其他 `Throwable` 才 `LOGGER.error`）
> → `getOrCreate` **返回一个全新的空 `StructureTemplate` 并把它缓存**。
>
> 结果：worldgen 注册表**照常加载**（不会 `Failed to load registries`）、
> 结构**照常被选中、照常"生成"** —— 生成出来的是**空气**。
> 遗迹永远不出现，**零日志、零报错**。
>
> 所以"缺 NBT"在 `check_resources.py` 里是 **`pending`**（已知排期欠账，不阻塞退出码），
> 而不是 FAIL —— 但它**必须**在 WS-G2 收尾时清空。
