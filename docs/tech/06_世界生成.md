# 06 · 世界生成（忆者遗迹）

> 本文件是 `mnemosyne`（忆海 / 记忆·认知流派）技术文档集的第 6 篇。
> 所有 JSON 结构均**逐字取自** `irons_spellbooks-1.20.1-3.16.3` 的实装文件，可直接作为模板使用。
> 配套非技术文档：`08_建筑_忆者遗迹.md`（世界观、分区设计、战利品设计）。

---

## 〇、一句话结论

**忆者遗迹的生成 100% 是纯数据驱动（JSON + NBT），零 Java 代码。**

你需要写 6 类文件：

| # | 文件 | 数量 | 说明 |
|---|---|---|---|
| 1 | `worldgen/structure/memory_ruin.json` | 1 | 结构定义（jigsaw 配置） |
| 2 | `worldgen/structure_set/memory_ruin.json` | 1 | 放置规则（间距/盐值） |
| 3 | `worldgen/template_pool/memory_ruin/*.json` | 3~5 | 拼图池 |
| 4 | `worldgen/processor_list/memory_ruin_randomization.json` | 1 | 方块随机化（苔藓/裂缝/风化） |
| 5 | `tags/worldgen/biome/has_structure/memory_ruin.json` | 1 | 允许生成的生物群系 |
| 6 | `structures/memory_ruin/*.nbt` | N 个 | 结构本体（用结构方块导出） |

**唯一的 Java 部分是自定义战利品函数**，而战利品函数官方已经提供（`randomize_spell`），所以你连这个都不用写。

## 一、真实案例解剖：`pyromancer_tower`

`pyromancer_tower`（烈焰术士塔）是 ISS 里**最完整的单结构案例**：地表塔 + 地下迷宫 + 自定义地形元素 + 随机化处理器。**忆者遗迹直接对标它。**

│   ├── template_pool/pyromancer_tower/

### 1.2 结构定义（实测原文）

`worldgen/structure/pyromancer_tower.json`：

```json
{
  "type": "minecraft:jigsaw",
  "liquid_settings": "ignore_waterlogging",
  "start_pool": "irons_spellbooks:pyromancer_tower/start_pool",
  "size": 7,
  "biomes": "#irons_spellbooks:has_structure/pyromancer_tower",
  "terrain_adaptation": "beard_thin",
  "use_expansion_hack": false,
  "start_height": {
    "absolute": 0
  },
  "project_start_to_heightmap": "WORLD_SURFACE_WG",
  "step": "underground_decoration",
  "max_distance_from_center": 96,
  "spawn_overrides": {
  }
}
```

**字段逐一解释**：

| 字段 | 值 | 含义 |
|---|---|---|
| `type` | `minecraft:jigsaw` | 拼图结构（唯一实用类型） |
| `liquid_settings` | `ignore_waterlogging` | ⚠️ **1.20.1 里这个字段是惰性的** —— 见下方更正 |
| `start_pool` | 池 ID | 从哪个模板池开始拼 |
| `size` | `7` | ⭐ **最大递归深度**，不是方块数。7 表示"最多拼 7 层" |
| `biomes` | 标签 ID | 允许生成的群系（指向 `tags/worldgen/biome/has_structure/...`） |
| `terrain_adaptation` | `beard_thin` | ⭐ 地形适配：`none` / `beard_thin` / `beard_box` / `bury` |
| `use_expansion_hack` | `false` | 是否扩展村庄式边界，自定义结构**一律 false** |
| `start_height` | `{"absolute": 0}` | 起始高度；也可用 `{"type":"uniform","min_inclusive":{...},"max_inclusive":{...}}` |
| `project_start_to_heightmap` | `WORLD_SURFACE_WG` | ⭐ 把起始点投影到地表（`WORLD_SURFACE_WG` 不加载区块，最快） |
| `step` | `underground_decoration` | 生成阶段，决定与其它结构的先后 |
| `max_distance_from_center` | `96` | ⭐ **硬上限 128**，超过游戏崩溃 |
| `spawn_overrides` | `{}` | 结构内刷怪覆盖（空 = 用群系默认刷怪） |

#### ⚠️ 更正（2026-09-17）：`liquid_settings` 在 1.20.1 是**惰性字段**

上面那份 ISS 原文里确实有 `"liquid_settings": "ignore_waterlogging"`，
但**这不代表它在 1.20.1 有效**。实测（`javap` 反编译 1.20.1 的
`net.minecraft.world.level.levelgen.structure.structures.JigsawStructure`）：

```
private final Holder<StructureTemplatePool> startPool;
private final Optional<ResourceLocation> startJigsawName;
private final int maxDepth;
private final HeightProvider startHeight;
private final boolean useExpansionHack;
private final Optional<Heightmap.Types> projectStartToHeightmap;
private final int maxDistanceFromCenter;
```

**没有 `liquidSettings` 这个字段**（`liquid_settings` 是 1.21 才加进 `JigsawStructure` 的）。
`RecordCodecBuilder` 生成的 codec 对**未知键是宽容的** —— 不读、不报错、不生效。

结论：
- 它**不会**让存档加载失败（ISS 自己就带着它，一切正常）；
- 但它**也不会**做任何事，是一份从高版本抄过来的死元数据；
- **我们的 `structure/memory_ruin.json` 里已经删掉它** ——
  留着一个"看起来在防积水、实际什么也没做"的字段，比没有更糟。

要真的控制含水，用 `structures` 里显式写 `minecraft:water` / `waterlogged` 方块状态。

### 1.3 ⭐ `terrain_adaptation` 的四种取值 —— 最容易搞错的地方

| 值 | 效果 | 用在哪 |
|---|---|---|
| `none` | 完全不修改地形 | 悬空结构、地下的封闭房间 |
| `beard_thin` | 在结构底部**薄薄地铺一层**地基 | **地表建筑**（塔、小屋、遗迹） |
| `beard_box` | 在结构底部**铺一圈盒状地基** | 需要更稳地基的地表建筑 |
| `bury` | 用土**掩埋**结构外部 | **地下结构**（墓穴、地牢） |

**实测证据**：`catacombs.json`（地下墓穴）用 `"terrain_adaptation": "bury"`，而 `pyromancer_tower.json` / `mountain_tower.json`（地表塔）用 `beard_thin`。

**忆者遗迹的取值**：
- 主结构（地表下沉的环形遗迹）→ `beard_thin`
- 地下档案库（`08_建筑_忆者遗迹.md` 的"沉没档案馆"变体）→ `bury`

### 1.4 ⭐ `step` 生成阶段 —— 决定"谁先谁后"

`GenerationStep.Feature` 的 10 个阶段（按执行顺序）：

| 顺序 | 值 | 说明 |
|---|---|---|
| 1 | `raw_generation` | 地形原始生成 |
| 2 | `lakes` | 湖泊 |
| 3 | `local_modifications` | 地形局部修改 |
| 4 | `underground_structures` | 地下结构 |
| 5 | `surface_structures` | **地表结构**（mountain_tower 用这个） |
| 6 | `carvers` | 洞穴/峡谷雕刻 |
| 7 | `freeze_top_layer` | 顶层结冰 |
| 8 | `vegetal_decoration` | 植被 |
| 9 | `underground_decoration` | **地下装饰**（pyromancer_tower / catacombs 用这个） |
| 10 | `top_layer_modification` | 顶层修改 |

**为什么 pyromancer_tower 用 `underground_decoration` 而不是 `surface_structures`？**

因为它**主体在地下**，地表只有一个塔。用 `underground_decoration` 可以保证：
- 地下的部分在**洞穴雕刻之后**生成，不会被洞穴挖穿
- 地表的塔在**植被之前**生成，会被草/树自然包围

**忆者遗迹建议**：主体在地下 → `underground_decoration`（对标 pyromancer_tower）。

### 1.5 放置规则（实测原文）

`worldgen/structure_set/pyromancer_tower.json`：

```json
{
  "structures": [
    {
      "structure": "irons_spellbooks:pyromancer_tower",
      "weight": 1
    }
  ],
  "placement": {
    "salt": 1512684,
    "spacing": 85,
    "separation": 50,
    "type": "minecraft:random_spread"
  }
}
```

**⭐ `salt` 是最容易踩的坑**：

> `"salt"` 必须**全局唯一**，不能和任何其它结构（包括原版和其它模组）相同。
> 相同 salt 会导致两个结构**永远生成在完全相同的位置**，或者干脆不生成。

实测 ISS 使用的 salt：

| 结构 | salt |
|---|---|
| `pyromancer_tower` | `1512684` |
| `catacombs` | `1794563212` |

**忆者遗迹的 salt 取值建议**：

```java
// 用你的 modid 的 hashCode 派生，保证唯一
int salt = "mnemosyne:memory_ruin".hashCode();
// 或者直接手填一个 8 位数，但要避开上表
```

推荐：`1852304719`（避开已知值）。**改完后务必用 `/locate structure mnemosyne:memory_ruin` 实测。**

**`spacing` / `separation` 的含义**：

| 字段 | 单位 | 含义 |
|---|---|---|
| `spacing` | 区块 | ⭐ **平均**间隔（不是最小值）。85 = 平均每 85 区块尝试一次 |
| `separation` | 区块 | ⭐ **最小**间隔。**必须小于 `spacing`**，否则结构会重叠 |

**参照表（实测）**：

| 结构 | spacing | separation | 稀有度 |
|---|---|---|---|
| `mountain_tower` | 较小 | — | 较常见 |
| `catacombs` | 72 | 48 | 中等 |
| `pyromancer_tower` | 85 | 50 | 较稀有 |
| `citadel` | 更大 | — | 极稀有 |

**忆者遗迹建议**：忆者遗迹是核心内容（记忆碑是主要解锁途径），**不能太稀有**。

```json
"placement": {
  "salt": 1852304719,
  "spacing": 64,
  "separation": 40,
  "type": "minecraft:random_spread"
}
```

比 `catacombs` 略密，因为忆海流派**完全依赖遗迹获取法术**（见 `05_卷轴与法术书.md` §5.2 做法 C）。

`tags/worldgen/biome/has_structure/pyromancer_tower.json`：

  "values": [
    "#minecraft:is_hill",
    "#minecraft:is_forest",
    "#forge:is_plains",
    "#forge:is_swamp"
  ]
}
```

**忆者遗迹的群系标签**（对标 `08_建筑_忆者遗迹.md` 的三个变体）：

```json
{

    "#minecraft:is_forest",
    "#minecraft:is_taiga",
    "#minecraft:is_jungle",
    "#forge:is_plains",
    "#minecraft:is_hill",
    "#minecraft:is_mountain"

**设计意图**：
- 森林/丛林 → 「藤蔓缠绕的沉没档案馆」变体
- 山地/丘陵 → 「风蚀之塔」变体
- 平原 → 「铭忆墓窟」变体（埋在地下）

## 二、模板池（Template Pool）

### 2.1 标准写法（实测原文）

`worldgen/template_pool/mountain_tower_pool.json`：

```json
{
  "name": "irons_spellbooks:mountain_tower_pool",
  "fallback": "minecraft:empty",
  "elements": [
    {
      "weight": 1,
      "element": {
        "location": "irons_spellbooks:mountain_tower",
        "processors": "irons_spellbooks:weather_stone_blocks",
        "projection": "rigid",
        "element_type": "minecraft:single_pool_element"
      }
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `name` | 池的 ID，**必须与 `start_pool` 指向的一致** |
| `fallback` | ⭐ 所有元素都失败时用的池。`minecraft:empty` = 什么都不生成 |
| `elements[].weight` | 相对权重（不用加起来等于 100） |
| `element.location` | NBT 路径（不含 `.nbt`） |
| `element.processors` | 处理器列表 ID |
| `element.projection` | ⭐ `rigid`（刚性，不随地形弯曲）/ `terrain_matching` |
| `element.element_type` | ⭐ `minecraft:single_pool_element` 或 ISS 自定义类型 |

### 2.2 ⭐ `projection` 的选择

| 值 | 效果 | 用途 |
|---|---|---|
| `rigid` | **刚性**：整个结构保持原样，不扭曲 | 建筑、房间、塔（**99% 的情况**） |
| `terrain_matching` | 地形匹配：结构会随地形起伏变形 | 道路、桥梁、围墙 |

**忆者遗迹一律用 `rigid`。**

### 2.3 ⭐ ISS 自定义元素类型 `individual_terrain_element`

`pyromancer_tower/start_pool.json` 用了官方标准之外的自定义类型：

```json
{
  "weight": 1,
  "element": {
    "location": "irons_spellbooks:pyromancer_tower/tower",
    "processors": "irons_spellbooks:pyromancer_tower_randomization",
    "projection": "rigid",
    "element_type": "irons_spellbooks:individual_terrain_element",
    "terrain_adjustment": "beard_thin"
  }
}
```

**`individual_terrain_element` 是 ISS 注册的自定义池元素类型**，比原版 `single_pool_element` 多一个 `terrain_adjustment` 字段，可以**让池里每个元素用不同的地形适配方式**。

实测证据：在 `cellar_dungeon.json` 里，同一个池中：
- 房间元素 → `"terrain_adjustment": "bury"`（埋起来）
- 装饰元素 → `"terrain_adjustment": "none"`（不碰地形）

⚠️ **`irons_spellbooks:individual_terrain_element` 是 ISS 注册的，你的模组可以直接用**（因为它只是 JSON 里的字符串 ID，只要 ISS 加载了就能解析）。

**建议**：忆者遗迹**直接复用** `irons_spellbooks:individual_terrain_element`，不要自己注册。这样你的地表遗迹用 `beard_thin`、地下房间用 `bury`，一个结构搞定。

### 2.4 ⭐ 三种池的组织模式

从 `pyromancer_tower` 的实测结构可以总结出三种模式：

**模式 A：单元素池（入口）**

`start_pool.json` —— 只有一个元素，就是"塔本体"：

```json
{
  "name": "mnemosyne:memory_ruin/start_pool",
  "fallback": "minecraft:empty",
  "elements": [
    {
      "weight": 1,
      "element": {
        "location": "mnemosyne:memory_ruin/ruin_main",
        "processors": "mnemosyne:memory_ruin_randomization",
        "projection": "rigid",
        "element_type": "irons_spellbooks:individual_terrain_element",
        "terrain_adjustment": "beard_thin"
      }
    }
  ]
}
```

**模式 B：加权随机池（地下房间）**

`cellar_dungeon.json` —— 16 个元素，权重 1~8：

```json
{
  "name": "mnemosyne:memory_ruin/chamber_pool",
  "fallback": "mnemosyne:memory_ruin/chamber_fallback",
  "elements": [
    {
      "weight": 8,
      "element": {
        "location": "mnemosyne:memory_ruin/chamber/corridor",
        "processors": "mnemosyne:memory_ruin_randomization",
        "projection": "rigid",
        "element_type": "irons_spellbooks:individual_terrain_element",
        "terrain_adjustment": "bury"
      }
    },
    {
      "weight": 4,
      "element": { "location": "mnemosyne:memory_ruin/chamber/archive_vault", "...": "..." }
    },
    {
      "weight": 1,
      "element": { "location": "mnemosyne:memory_ruin/chamber/mnemonic_core", "...": "..." }
    }
  ]
}
```

**权重设计经验（从实测反推）**：

| 权重 | 类型 | 含义 |
|---|---|---|
| 8 | 走廊、死路、普通房间 | 高频填充 |
| 4 | 特色房间（牢房、储藏、研究） | 中频 |
| 1~2 | 稀有房间（研究台、雕像通道、核心） | 低频惊喜 |

**模式 C：回退池（防止生成失败）**

```json
{
  "name": "mnemosyne:memory_ruin/chamber_fallback",
  "fallback": "minecraft:empty",
  "elements": [
    {
      "weight": 1,
      "element": {
        "location": "mnemosyne:memory_ruin/chamber/sealed_wall",
        "processors": "mnemosyne:memory_ruin_randomization",
        "projection": "rigid",
        "element_type": "irons_spellbooks:individual_terrain_element",
        "terrain_adjustment": "bury"
      }
    }
  ]
}
```

**为什么需要回退池**：jigsaw 拼接时，如果某个方向的连接点找不到匹配的模板，就会用 `fallback`。用一堵"封死的墙"回退，比留一个洞（会导致结构漏进地形）好得多。

**ISS 实测的 `fallback` 链**（两层）：

```
cellar_dungeon.json  →  fallback: pyromancer_cellar_fallback_pool
                              ↓ fallback: fallback_wall_thin
                                   ↓ fallback: minecraft:empty
```

**忆者遗迹照抄这个三层回退链。**

## 三、处理器列表（Processor List）

### 3.1 实测原文（节选）

`worldgen/processor_list/pyromancer_tower_randomization.json`：

```json
{
  "processors": [
    {
      "processor_type": "irons_lib:randomize_player_statue"
    },
    {
      "processor_type": "minecraft:rule",
      "rules": [
        {
          "input_predicate": {
            "block": "minecraft:stone_bricks",
            "predicate_type": "minecraft:random_block_match",
            "probability": 0.25
          },
          "location_predicate": {
            "predicate_type": "minecraft:always_true"
          },
          "output_state": {
            "Name": "minecraft:cracked_stone_bricks"
          }
        },
        {
          "input_predicate": {
            "block": "minecraft:mossy_stone_bricks",
            "predicate_type": "minecraft:random_block_match",
            "probability": 0.3
          },
          "location_predicate": {
            "predicate_type": "minecraft:always_true"
          },
          "output_state": {
            "Name": "minecraft:stone_bricks"
          }
        }
      ]
    }
  ]
}
```

### 3.2 `minecraft:rule` 的结构

```json
{
  "input_predicate": {
    "block": "被替换的方块",
    "predicate_type": "minecraft:random_block_match",
    "probability": 0.25
  },
  "location_predicate": { "predicate_type": "minecraft:always_true" },
  "output_state": {
    "Name": "替换成的方块",
    "Properties": { "axis": "z" }
  }
}
```

| 部分 | 说明 |
|---|---|
| `input_predicate` | 匹配条件。`random_block_match` = 匹配该方块 + 按概率随机 |
| `location_predicate` | 位置条件。`always_true` = 任意位置都适用 |
| `output_state` | 替换结果。`Properties` 可选（如楼梯朝向、木头轴向） |

**其它常用 `predicate_type`**：

| 类型 | 作用 |
|---|---|
| `minecraft:always_true` | 恒真 |
| `minecraft:random_block_match` | 随机匹配方块 |

  实际概率因此是：35% 裂开，65% × 12% = **7.8% 变空气**，其余 57.2% 完好。
  把两条顺序调过来会得到"12% 变空气 + 88% × 35% 裂开"，观感明显不同。

> ⚠️ **本节的示例与 `processor_list/memory_ruin_randomization.json` 必须逐字同步。**
> 2026-09-17 发现代码里**漏掉了最后两条 `mnemonic_bricks` 规则**（只有 7 条），
> 表现是：遗迹的墙体完全不会风化 —— 而墙的主体就是铭忆砖，
> 等于**整个风化系统一点都没生效**，且没有任何报错。已补齐。

⚠️ **注意顺序**：`rules` 是**按顺序依次尝试**的，一条匹配成功就停止。所以"裂开"的规则要放在"变空气"之前。

### 3.4 ⚠️ `irons_lib:randomize_player_statue` 不要用

实测中出现了 `{"processor_type": "irons_lib:randomize_player_statue"}`。这是 **`irons_lib` 这个前置库**注册的处理器（把玩家雕像的皮肤随机化）。

**忆者遗迹不要用这个** —— 它依赖 `irons_lib`，虽然 ISS 3.16.3 已经内嵌了 `irons_lib`，但你的模组不应该依赖 ISS 的内部库。

## 四、NBT 结构文件的制作流程

> ⭐ **2026-09-17 起：23 个模板改为脚本生成，不再用结构方块手搓。**
>
> ```
> python tools/gen_structure_nbt.py          # 生成 + 自检（自检不过就不写文件）
> python tools/gen_structure_nbt.py --check  # 只自检
> python tools/inspect_structure.py <dir>    # 独立解析器回读校验
> ```
>
> **为什么放弃游戏内流程**：`4.1` 那套要 runClient、要人工框选、23 个文件要重复 23 次，
> 而且**无法被校验** —— 手搓出来的 NBT 少一个拼图块、`name`/`target` 配错，
> 游戏里只表现为"遗迹里有个洞"或"遗迹只有一间房"，**零日志零报错**。
> 脚本把 23 个模板变成可复现的代码，并在写文件前跑一遍结构自检。
>
> `4.1` / `4.2` 保留作为**背景知识**（理解拼图机制仍然需要），但不要再照着做。

### 4.0 ⭐⭐ 实测得到的 NBT 格式硬事实（读 MC 反编译源码 + 解 ISS 的 236 个 NBT）

| 事实 | 依据 |
|---|---|
| **必须写满整个包围盒** | ISS 的 `battleground/origin.nbt` 尺寸 26×17×26，方块数 **11492** = 26×17×26；`cellar_dungeon/wall.nbt` 7×7×1 → 方块数 **49**。两处都恰好等于包围盒体积 |
| **未列出的格子不是空气，而是"保持世界原样"** | `StructureTemplate.placeInWorld` 只放置 `blocks` 里列出的格子。所以只写墙体不写走道 → 埋在地下的遗迹走道里**留的是原地石头**：结构生成了、零报错、玩家挖进去发现是实心的 |
| 根标签名是**空串**，容器是 **gzip**（不是 zlib） | 逐字节比对 ISS 的文件 |
| `DataVersion` 只是元数据 | `StructureTemplate.load` 不经过 DataFixer。ISS 自己都不一致（3120 / 3953 混用）；我们写 1.20.1 真值 **3465** |
| `orientation` 只有 **12 个合法值** | `FrontAndTop` 的枚举：`down_east/north/south/west`、`up_*`、`*_up`。写错一个字母 → 该方块**静默变成空气** → 连接口凭空消失 |
| `final_state` 由**自动挂上**的处理器替换 | `SinglePoolElement.place()` 里有 `structureplacesettings.addProcessor(JigsawReplacementProcessor.INSTANCE)`。⚠️ `final_state` 写了不存在的方块 id 会抛 `RuntimeException` —— 这是少数会**炸存档**的错误 |
| `final_state: minecraft:structure_void` = 删掉这格 | `JigsawReplacementProcessor` 对 `STRUCTURE_VOID` 返回 `null` |
| 连接匹配规则 | `parent.target.equals(child.name)` + 两个 `front` 必须反向 + （`aligned` 时）`top` 必须相同 |
| ⭐ **`joint` 只从父块读** | `JigsawBlock.canAttach` 只读 `parent.nbt().getString("joint")`。所以"水平口用 `rollable`、竖直口用 `aligned`"这条规则是作用在**父件**上的 |
| ⭐ **竖直连接必须 `aligned`** | 竖直 front（up/down）绕 Y 轴旋转**永远是 up/down** → 4 个旋转的 front 全都满足"反向"，只有 `aligned` 的 `top` 检查才能把旋转钉成唯一一个。用 `rollable` 会让楼梯件随机转 90° 而错位 |
| **子件的拼图块必须在包围盒边缘** | 子件位置 = `父拼图块位置 + 父front − 旋转后的子拼图块局部位置`。拼图块放正中 → 子件有一半插进父件 → 碰撞检测拒掉整次放置 → "遗迹只有第一间房" |
| `pool: "minecraft:empty"` 是"到此为止"的标准写法 | `Pools.EMPTY` 是真实注册的空池，且 `JigsawPlacement` 专门写了 `!holder.is(Pools.EMPTY)` 豁免它的警告 → 安全且**静默** |
| **回退池不是"最后手段"** | `tryPlacingChildren` 里 `list.addAll(pool.getShuffledTemplates())` 与 `list.addAll(pool.getFallback()...)` 是**并列追加**的；且到达 `maxDepth` 时**只剩回退池**。所以回退件的权重是真实生效的 |
| 缺 `.nbt` 的真实表现 | `StructureTemplateManager.getOrCreate` 找不到文件时 `new StructureTemplate()`（空）**并缓存** → 结构照常被选中、照常"生成"、**生成的是空气**。日志里只有一条 `Couldn't load structure <id>` 的 ERROR，极易漏掉 |

### 4.1 制作步骤（完全在游戏内完成）

```
1. 进入一个创造模式超平坦世界
2. 用 /give @s structure_block 拿到结构方块
3. 建造你的结构（记住：不要用命令放置方块，结构方块只记录它自己保存范围内的方块）
4. 放置结构方块，右键打开 GUI
5. 模式设为 SAVE
6. 输入结构名称，例如 memory_ruin/ruin_main
7. 调整结构大小（角落模式 CORNER）框住整个建筑
8. 点击 DETECT 自动检测范围，再点 SAVE
9. 文件出现在 .minecraft/saves/<世界名>/generated/minecraft/structures/memory_ruin/ruin_main.nbt
10. 把 .nbt 复制到 src/main/resources/data/mnemosyne/structures/memory_ruin/ruin_main.nbt
```

### 4.2 ⭐ 连接点（Jigsaw Block）—— 拼图的核心

**jigsaw 结构靠"连接点"互相拼接。** 每个连接点是一个 `jigsaw` 方块。

放置方法：

```
1. /give @s jigsaw
2. 在墙上放置 jigsaw 方块
3. 右键配置：
   - Target Pool（目标池）：下一个拼图从哪个池里选
   - Name（自己的名字）：例如 mnemosyne:corridor
   - Target Name（目标名字）：例如 mnemosyne:corridor
   - Turns into（拼完后变成什么方块）：一般是 minecraft:air 或结构的一部分
   - Joint Type（连接类型）：aligned（对齐）或 rollable（可旋转）
4. 用"旋转模式"（结构方块 GUI 里的 ROTATE）确认朝向
```

**命名规则（必须严格遵守）**：

- 连接点是**成对匹配**的：A 的 `Target Name` 必须等于 B 的 `Name`
- 用命名空间前缀避免冲突：`mnemosyne:corridor`、`mnemosyne:chamber_in`
- ⚠️ **更正（2026-09-17）：同一个池里的所有口共用同一个 `name`/`target`，不要按方向分开命名。**
  实测 ISS 的 `cellar_dungeon/junction.nbt` —— 它的 **4 个**拼图块 name 与 target
  **全是** `minecraft:pyromancer_cellar_dungeon_piece`。
  原先这里写"北出口叫 `corridor_north`、南入口叫 `corridor_south`"，那是**错的**：
  子件会被尝试 4 个旋转，旋转本身就能把"东口"对到"西口"上；
  按方向分开命名只会让 `target` 多出一堆必须逐个配对的组合，**配错一处就静默断开**。
  （方向靠 `orientation` 的 front 表达，不靠名字。）

**实测参考**（`pyromancer_tower` 的连接点命名）：`irons_spellbooks:pyromancer_tower/cellar_dungeon/junction` 等。

### 4.3 ⭐ 结构方块的 `Turns into` 字段

拼完之后，jigsaw 方块会变成 `Turns into` 指定的方块。

| 场景 | 推荐值 |
|---|---|
| 两个房间的连通口 | `minecraft:air`（打通） |
| 房间的备用出口（不一定被用到） | 一堵墙的方块（如 `mnemosyne:mnemonic_bricks`） |

**为什么重要**：如果所有连接口都是 `air`，拼图没用到那个口时就会留一个**通向虚空的洞**。所以**所有"可能不被用到"的连接点，`Turns into` 都应该是一堵墙**。

### 4.4 ⚠️ NBT 文件的三个坑

| 坑 | 现象 | 解决 |
|---|---|---|
| **结构方块版本号** | 用高版本存档导出的 nbt 放进 1.20.1 会加载失败 | 必须在 **1.20.1** 环境里导出 |
| **相对坐标原点** | 结构生成位置偏移 | 用 `CORNER` 模式明确框选，不要依赖 DETECT |
| **方块实体丢失** | 箱子变成空的 | 保存时确保箱子在框选范围内，且已放好战利品表 |

### 4.5 战利品表的挂载（在结构里挂，不是在 JSON 里挂）

箱子的战利品表是**存在方块实体 NBT 里**的：

```nbt
{
  id: "minecraft:chest",
  LootTable: "mnemosyne:chests/memory_ruin/vault"
}
```

**做法**：在建造结构时，用命令给箱子设置战利品表：

```
/data merge block <x> <y> <z> {LootTable:"mnemosyne:chests/memory_ruin/vault"}
```

然后再保存结构。这样生成的箱子里就有战利品了。

### 6.4 ⚠️ `quality` 与稀有度的对应关系

`quality` 是 0.0~1.0 的浮点，内部映射到稀有度。实测反推：

| `quality` 区间 | 大致稀有度 |
|---|---|
| 0.0 ~ 0.4 | Common / Uncommon |
| 0.4 ~ 0.6 | Uncommon / Rare |
| 0.6 ~ 0.8 | Rare / Epic |
| 0.8 ~ 1.0 | Epic / Legendary |

**依据**：实测 `pyromancer_tower/burnt_chest.json` 用 `quality {min: 0.6, max: ...}`（烈焰塔是中等偏难的结构），而 `generic_magic_treasure.json` 用 `quality {min: 0.0, max: 0.60}`（通用宝箱，偏低阶）。

**忆者遗迹的 quality 分配建议**：

| 宝箱类型 | quality | 理由 |
|---|---|---|
| 普通储藏箱 | 0.0 ~ 0.4 | 主要是材料 |
| 档案库 | 0.4 ~ 0.7 | 中阶法术 |
| 记忆核心 | 0.7 ~ 1.0 | 保证高阶法术 |

### 8.1 ⚠️ 未裁决的设计冲突：遗迹到底要不要有忆魇

2026-09-17 集成时发现两份文档结论相反，**至今没有裁决**：

| 出处 | 结论 |
|---|---|
| `08_建筑_忆者遗迹.md` §7.3（**设计文档**，带理由） | 「遗迹**不生成任何新的怪物**。它是一个**纯粹的探索点**，而不是战斗副本。」<br>理由：记忆流派的核心是"探索与发现"，玩家该带着好奇心走进去 |
| `08_建筑_忆者遗迹.md` §4.3 | 但**原版骷髅**的刷怪点是想要的（"死去的探险者"，增加危险感） |
| 本文 §5.2 的示例 JSON + §七 验收表第 11 条 | 忆魇**应该**在遗迹里刷（"专属怪物能刷 → 忆魇出现"） |
| 本文 §八 的交叉引用 | 把忆魇的设计指向 `02_核心机制_遗忘与能力映射.md` —— **那份文档里一个字都没有** |

**当前的处置**（可一行改动回退）：

- 忆魇实体**已完整实现**（`entity/MemoryWraithEntity` + 渲染器 + 刷怪蛋），
  可以用 `/summon mnemosyne:memory_wraith` 或刷怪蛋生成；
- 但 `worldgen/structure/memory_ruin.json` 的 `spawn_overrides` **保持为空** ——
  服从设计文档 `08` 的"纯探索点"红线，**不**让它自然刷；
- 要开启自然刷怪，在 `spawn_overrides` 里加一条即可（见 §5.2 的示例）——
  **但在裁决这个冲突之前不要加。**

⚠️ 顺带一提：`spawn_overrides` 是 `Map<MobCategory, ...>`，**不能往里塞 `"_comment"` 之类的未知键** ——
未知键会在解析 `MobCategory` 时失败，而 worldgen 注册表解析失败 = **存档直接加载不了**
（不是静默降级）。注释只能写在本文档里。
