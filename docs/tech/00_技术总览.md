## 二、依赖矩阵

| 依赖 | 版本 | 作用 | 引入方式 |
|---|---|---|---|
| **Iron's Spells 'n Spellbooks** | `1.20.1-3.16.3` | 目标模组本体 | `compileOnly :api` + `runtimeOnly` 完整包 |
| **irons_lib** | `1.20.1-2.1.0` | ⭐ **ISS 3.16.x 的强制前置**（ISS 自己的 mods.toml 声明 `[1.20.1-2,1.20.1-3)`） | `runtimeOnly` |
| **Curios API** | `5.14.1+1.20.1` | 法术书槽位、饰品槽 | `implementation :api` + `runtimeOnly` |
| **GeckoLib** | `1.20.1:4.7.1.1` | ISS 的模型动画前置 | `runtimeOnly` |
| **player-animator** | `1.0.2-rc1+1.20` | ISS 的施法动作前置 | `implementation` |
| **Caelus** | `3.1.0+1.20` | ISS 的鞘翅飞行前置 | `compileOnly :api` + `runtimeOnly` |

> **⚠️ 版本下限是 ISS 定的，不是我们定的**（Phase 0 实测，2026-09-15）：
> `runClient` 时 Forge 的 `ModSorter` 报
> `Missing or unsupported mandatory dependencies: Mod ID: 'curios', Requested by: 'irons_spellbooks', Expected range: '[5.14.1+1.20.1,)', Actual version: '5.4.7+1.20.1'`。
> 所以 **Curios 必须 ≥ 5.14.1+1.20.1**（`5.4.7` 是 ISS 旧版本的要求，早已作废），
> 且 **必须显式声明 `irons_lib`** —— ISS 的 POM 里没有任何依赖，Maven 不会自动带进来。
> 详见 `07` §十 坑 #9。

### 关键：ISS 的两种依赖形态

```gradle
// ⚠️ 编译期必须用「完整 jar」，不能用 :api 分类器（Phase 2 实测，见下方）
compileOnly fg.deobf("io.redspace:irons_spellbooks:1.20.1-3.16.3")
// 运行期：完整模组
runtimeOnly fg.deobf("io.redspace:irons_spellbooks:1.20.1-3.16.3")
```

> **⭐ 为什么不能用 `:api` 分类器**（Phase 2 实测，2026-09-15）：
>
> `:api` jar 里**缺** `io.redspace.ironsspellbooks.damage.SpellDamageSource`
> （实测 `jar tf ...-api.jar | grep damage` 只返回 `api/events/SpellDamageEvent` 和
> `api/spells/PlaceholderDamageType`，没有 `SpellDamageSource`）。
> 而 `AbstractSpell.getDamageSource(Entity)` 的返回类型**正是它**，实测报错：
>
> ```
> 错误: 无法访问SpellDamageSource
>         target.hurt(spell.getDamageSource(caster), 5.0F);
> 找不到 io.redspace.ironsspellbooks.damage.SpellDamageSource 的类文件
> ```
>
> 后果是**任何要造成伤害的法术都编译不过**，而 §三 又强制要求
> "伤害必须走 `getDamageSource()`"（否则目标的学派抗性完全不起作用）。
> 也就是说 **`:api` 分类器和伤害规范自相矛盾**，必须放弃 `:api`。
>
> 仍然用 `compileOnly` → ISS **不会**被打进我们的 jar，没有再分发风险。

**这条规则决定了你能写什么、不能写什么**：

| 包路径 | 编译期可见？ | 说明 |
|---|---|---|
| `io.redspace.ironsspellbooks.api.*` | ✅ **可见** | 官方 API，直接调用 |
| `io.redspace.ironsspellbooks.damage.SpellDamageSource` | ✅ 可见（**必须用完整 jar**） | 伤害管线入口 |
| `io.redspace.ironsspellbooks.item.*` | ⚠️ 可见但**不准用** | 例如 `Scroll`、`SpellBook`、`UpgradeOrbItem` |
| `io.redspace.ironsspellbooks.capabilities.*` | ⚠️ 可见但**不准用** | 例如 `SyncedSpellData`、`RecastInstance` |
| `io.redspace.ironsspellbooks.spells.*` | ⚠️ 可见但**不准用** | ISS 自带法术的具体实现 |
| `io.redspace.ironsspellbooks.entity.*` | ⚠️ 可见但**不准用** | ISS 的投射物实体 |

> **⚠️ 纪律**：完整 jar 让所有包都可见了，但**只准 import
> `io.redspace.ironsspellbooks.api.*` 与 `io.redspace.ironsspellbooks.damage.SpellDamageSource`**。
> 其他包（`item.` / `capabilities.` / `spells.` / `entity.` / `block.`）版本脆弱，
> 用了就等于把我们的模组绑死在 ISS 的某个小版本上。
> 需要那些能力时走**反射 + 缓存 + 失败降级**（模式见 `07` §6.2）。

> **遇到不可见的类怎么办**：两条路——
> ① **反射**（参考已有 addon 的 `SpellLearnHelper`，用缓存的 `Method` 反射调用，并做好失败降级）；
> ② **自己实现**（例如自己写一个卷轴物品，只实现 `api.item.IScroll` 接口）。

## 三、模组标识与命名空间

| 项 | 建议值 |
|---|---|
| `mod_id` | `mnemosyne`（全小写、ASCII、无空格） |
| 根包名 | `com.etbs31.mnemosyne`（**已冻结**，Phase 0 定稿） |
| jar 名 | `mnemosyne-1.0.0.jar`（**必须 ASCII**） |
| 资源命名空间 | `mnemosyne` |
| 显示名 | 写在 `mods.toml` 的 `displayName`（支持中文/UTF-8） |

> **踩坑提醒**：Forge 要求 **jar 文件名必须是 ASCII**，否则启动崩溃。中文模组名只能放在 `mods.toml` 里。同时 `gradle.properties` 由 Gradle 以 **ISO-8859-1** 读取，所以里面也只能放 ASCII——中文请写进 `src/main/resources/META-INF/mods.toml`（UTF-8）。

## 五、主类骨架（结构说明）

主类需要做四件事：

| 步骤 | 说明 |
|---|---|
| ① 拿到两条事件总线 | `FMLJavaModLoadingContext.get().getModEventBus()`（模组总线）+ `MinecraftForge.EVENT_BUS`（Forge 总线） |
| ② 注册所有 `DeferredRegister` | 把每个注册类里的 `DeferredRegister` 挂到模组总线上 |
| ③ 注册配置文件 | `ModLoadingContext.get().registerConfig(ModConfig.Type.SERVER, Config.SERVER_SPEC)`（以及 CLIENT） |
| ④ 在 `FMLCommonSetupEvent` 里注册网络通道 | 必须 `event.enqueueWork(...)`，因为网络注册要在主线程 |

**两条总线的分工**（最容易搞混的点）：

| 总线 | 用于 |
|---|---|
| **模组总线**（mod bus） | 注册表、`FMLCommonSetupEvent`、`FMLClientSetupEvent`、`EntityAttributeCreationEvent` |
| **Forge 总线**（forge bus） | 游戏运行期事件：`PlayerTickEvent`、`LivingHurtEvent`、`ItemAttributeModifierEvent`、`ServerStartingEvent` |

> 用 `@Mod.EventBusSubscriber(modid = MODID)` 的静态类会**自动注册到 Forge 总线**（除非显式指定 `bus = Bus.MOD`），不要在构造函数里重复 `register`。

## 六、构建与调试

```bash
./gradlew build          # 构建（build 任务已挂载自动拷贝到 mods 目录）
./gradlew runClient      # 启动开发客户端
./gradlew runServer      # 启动开发服务端
./gradlew runData        # 生成数据（战利品表、配方、标签等）
```

**已配置的自动部署**：`build.gradle` 里的 `copyToMinecraftMods` 任务会把构建产物自动拷到 PCL2 的 1.20.1-Forge 实例 mods 目录。可以通过参数覆盖：

```bash
./gradlew build -Ppcl2_mods_dir=D:/some/other/mods
```

## 七、编码约定

| 约定 | 说明 |
|---|---|
| 编码 | 所有 Java 编译强制 **UTF-8**（`options.encoding = 'UTF-8'`） |
| 反射容错 | 凡是调用 ISS 非 API 包的内容，**必须包在 try/catch 里并做降级**，且失败日志只打一次（避免刷屏） |
| 缓存 | 注册表扫描结果（法术池、物品目录、生物映射表）**必须缓存**，不要每次调用都遍历注册表 |
| 配置 | 所有数值走 `ForgeConfigSpec`，**不要硬编码** |
| 日志 | 用 `LogManager.getLogger(MODID)`，不要用 `System.out` |

## 八、必须避开的坑（已踩过的）

| 坑 | 说明 |
|---|---|
| **jar 名含中文 → 启动崩溃** | jar 名必须 ASCII，中文放 `mods.toml` |
| **`gradle.properties` 含中文 → 乱码** | Gradle 以 ISO-8859-1 读该文件，只能放 ASCII |
| **缺少 GeckoLib / player-animator → 开发环境崩溃** | 它们是 ISS 的运行时前置，即使你不直接调用也必须声明 |
| **Curios 版本抄了老攻略（5.4.7）→ `runClient` 崩在 `ModSorter`** | ISS 3.16.3 要求 `[5.14.1+1.20.1,)`。**`build` 能过，只有启动才暴露**（`07` §十 坑 #9） |
| **忘了声明 `irons_lib` → `runClient` 报 `[MISSING]`** | ISS 的 POM 里没有任何依赖，Maven 不会自动带；必须手动 `runtimeOnly` |
| **`curios` 不是 `compileOnly`** | 需要在代码里引用 `CuriosApi`，必须用 `implementation :api` |
| **网络通道在构造器里注册 → 崩** | 必须放到 `FMLCommonSetupEvent` + `enqueueWork` |
| **`SpellRegistry` 扫描不缓存 → 卡顿** | 115+ 个法术每次全扫会产生大量临时对象 |
| **学派白名单用 `contains(schoolId.toString())`** | 会因为命名空间永远不匹配导致全部被过滤，必须**分别匹配完整 id 和 path**，且大小写不敏感 |
| **`maxLevel` 与稀有度混淆** | 稀有度是由 `等级 / maxLevel` 比值算出来的，不是直接设的（见 [01 文档](01_ISS官方API参考.md) §五） |

## 九、与既有 addon 的兼容

本次技术方案完全遵循 ISS 官方 API，因此：

- 其他 addon 通过 `SpellRegistry` 注册的法术**能被本模组正常识别**（走 `getEnabledSpells()`）。
- 本模组注册的学派与法术**能被其他 addon 识别**（走 `SchoolRegistry.REGISTRY` / `SpellRegistry.REGISTRY`）。
- 生物能力映射表建议做成**可被数据包覆盖**的形式，方便整合包作者补充。
