## 二、学派注册

### 2.1 关键点

- ISS 的 `SchoolRegistry` 没有暴露公开的注册方法，**但暴露了注册表键**。
- 因此用标准 Forge 的 `DeferredRegister.create(注册表键, 你的命名空间)` 直接注册。

### 2.2 注册表键

```
irons_spellbooks:schools
```

对应 `SchoolRegistry.SCHOOL_REGISTRY_KEY`。

> **命名空间说明**：注册表键的命名空间是 `irons_spellbooks`（因为注册表是 ISS 建的），
> 但你传入 `DeferredRegister.create` 的第二个参数（你的命名空间）决定了**条目 id 的前缀**。
> 所以最终学派 id 是 `mnemosyne:memory`（命名空间 `mnemosyne`，路径 `memory`）。

### 2.2.1 ⭐ 实测：`makeRegistry()` 只能调一次（Phase 1 实测）

ISS 的 `SchoolRegistry` 源码（随 `:api` jar 发布，逐字）：

```java
public static final ResourceKey<Registry<SchoolType>> SCHOOL_REGISTRY_KEY =
        ResourceKey.createRegistryKey(ResourceLocation.fromNamespaceAndPath("irons_spellbooks", "schools"));
private static final DeferredRegister<SchoolType> SCHOOLS =
        DeferredRegister.create(SCHOOL_REGISTRY_KEY, "irons_spellbooks");
public static final Supplier<IForgeRegistry<SchoolType>> REGISTRY =
        SCHOOLS.makeRegistry(() -> new RegistryBuilder<SchoolType>().hasTags().disableSaving().disableOverrides());
```

**ISS 已经把这张表建好了。** `DeferredRegister.makeRegistry(...)` 对同一个注册表键**只能调用一次**，
第二次会抛异常。所以我们的写法是：

```java
private static final DeferredRegister<SchoolType> SCHOOLS =
        DeferredRegister.create(SchoolRegistry.SCHOOL_REGISTRY_KEY, MnemosyneMod.MODID);

public static void register(IEventBus modBus) {
    SCHOOLS.register(modBus);   // ✅ 只挂监听器，绝不调 makeRegistry
}
```

条目会被追加进 ISS 建好的那张表里。靠 `mods.toml` 的 `ordering="AFTER"` 保证 ISS 先建表。

> **也不需要 `event.enqueueWork(...)`**：`DeferredRegister` 走的是 Forge 的 `RegisterEvent`，
> 本身就在主线程触发。文档里要求的 `enqueueWork` 针对的是"在 `FMLCommonSetupEvent` 回调里
> **直接往注册表写数据**"的写法，我们没这么做。

### 2.2.2 ⭐ 实测：`displayName` 必须带颜色，否则 NPE

`SchoolType` 的 `displayStyle` 是从 `displayName.getStyle()` 取的：

```java
this.displayStyle = displayName.getStyle();
...
public Vector3f getTargetingColor() {
    return Utils.deconstructRGB(this.displayStyle.getColor().getValue());   // ← getColor() 可能是 null
}
```

**结论**：构造 `SchoolType` 时 `displayName` 必须带 style 颜色，例如
`Component.translatable("school.mnemosyne.memory").withStyle(Style.EMPTY.withColor(0x534AB7))`。
不带颜色 → 法术瞄准指示器取色时 NPE。

### 2.3 `SchoolType` 的 9 个构造参数

| 参数 | 类型 | 我们填什么 | 说明 |
|---|---|---|---|
| `id` | `ResourceLocation` | `mnemosyne:memory` | 学派 id |
| `focus` | `TagKey<Item>` | `mnemosyne:memory_focus` | **焦点物品标签**，不是物品本身 |
| `displayName` | `Component` | `Component.translatable("school.mnemosyne.memory")` | 翻译键 |
| `powerAttribute` | `Supplier<Attribute>` | 属性 ② | 学派法术强度 |
| `resistanceAttribute` | `Supplier<Attribute>` | 属性 ③ | 学派法术抗性 |
| `defaultCastSound` | `Supplier<SoundEvent>` | 音效 ⑤ | 默认施法音 |
| `damageType` | `ResourceKey<DamageType>` | `mnemosyne:memory` | 伤害类型 |
| `requiresLearning` | `boolean` | **`true`** | 必须学会才能抄写（配合忆碑解锁） |
| `allowLooting` | `boolean` | **`true`** | 允许出现在战利品里（忆者遗迹箱子） |

### 2.4 为什么 `requiresLearning = true`

对照邪术（Eldritch）：Eldritch 的 `requiresLearning` 是 true，玩家必须先找到"古老知识碎片"拼出手稿、消耗后学会某个法术，才能抄写与施放它。

记忆学派的设计与之呼应：**必须先读忆碑解锁法术，才能抄写**。这正是我们要的效果。

副作用：**未解锁的法术在法术书里显示为"未学习"**，并且抄写台会拒绝抄写。这正是我们想要的进度门槛。

### 2.5 为什么 `allowLooting = true`

我们的忆者遗迹箱子里要能开出记忆卷轴（设计文档 §7.2 的战利品表）。如果设为 `false`，随机卷轴生成会跳过记忆学派。

### 2.6 焦点物品标签

`focus` 是 `TagKey<Item>`，需要在数据包里定义：

`data/mnemosyne/tags/items/memory_focus.json`

```json
{
  "replace": false,
  "values": [
    "mnemosyne:memory_crystal"
  ]
}
```

> **路径与文件名都已冻结**：标签 id 是 `mnemosyne:memory_focus`，
> 对应 `data/mnemosyne/tags/items/memory_focus.json`
> （1.20.1 的目录名是 `tags/items/`，不是 1.21 的 `tags/item/`）。
> 对照 ISS：`data/irons_spellbooks/tags/items/fire_focus.json` = `{ "values": ["minecraft:blaze_rod"] }`。

> **这个标签同时被两处使用**：
> ① `SchoolRegistry.getSchoolFromFocus(ItemStack)` —— 用于判断"玩家是否手持学派焦点"（例如抄写台的学派归属判定）；
> ② 学派套装的合成配方 —— 用标签而不是硬编码物品 id，方便后续加"忆晶的不同变体"。

## 三、属性注册

### 3.1 注册位置

**属性注册在 Forge 原生注册表 `ForgeRegistries.ATTRIBUTES`**，不是 ISS 的注册表。

```java
// 伪代码，展示结构
DeferredRegister<Attribute> ATTRIBUTES =
        DeferredRegister.create(ForgeRegistries.ATTRIBUTES, "mnemosyne");
```

### 3.2 两个属性

| 属性 | id | 默认值 | 取值范围 | 说明 |
|---|---|---|---|---|
| 记忆法术强度 | `mnemosyne:memory_spell_power` | **1.0** | -100.0 – 100.0 | 乘算，与 `SPELL_POWER` 叠乘 |
| 记忆法术抗性 | `mnemosyne:memory_magic_resist` | **1.0** | -100.0 – 100.0 | **乘数**，1.0 = 不减免 |

> **⚠️ 这里是设计稿写错、实测推翻的一处**（Phase 1 实测，2026-09-15）。
>
> 设计稿原写"抗性默认 `0.0`，取值 0.0–1.0，表示减伤比例"。**这是错的，会导致零伤害。**
>
> 依据 —— `SchoolType` 源码（逐字，随 `:api` jar 发布）：
> ```java
> /**
>  * @return Returns raw resistance attribute value of the entity.
>  */
> public double getResistanceFor(LivingEntity livingEntity) {
>     return livingEntity.getAttributes().hasAttribute(resistanceAttribute.get())
>             ? livingEntity.getAttributeValue(resistanceAttribute.get()) : 1;
> }
> ```
> 抗性是**乘数**，缺省返回 `1`（不减免）。若按设计稿把默认值设成 `0.0`，
> 所有记忆法术的伤害会被乘以 0 —— 玩家一放技能就是零伤害，而且**不会报错**，极难排查。
>
> 依据二 —— ISS 自己的 `AttributeRegistry.java`（逐字）：
> ```java
> private static RegistryObject<Attribute> newResistanceAttribute(String id) {
>     return ATTRIBUTES.register(id + "_magic_resist",
>         () -> (new MagicPercentAttribute("attribute.irons_spellbooks." + id + "_magic_resist",
>                                          1.0D, -100, 100).setSyncable(true)));
> }
> private static RegistryObject<Attribute> newPowerAttribute(String id) {
>     return ATTRIBUTES.register(id + "_spell_power",
>         () -> (new MagicPercentAttribute("attribute.irons_spellbooks." + id + "_spell_power",
>                                          1.0D, -100, 100).setSyncable(true)));
> }
> ```
> **强度与抗性用的是同一个类、同一个默认值、同一个范围。**
>
> **正确写法**（我们实际采用的）：
> ```java
> public static final RegistryObject<Attribute> MEMORY_MAGIC_RESIST = ATTRIBUTES.register(
>         "memory_magic_resist",
>         () -> new MagicPercentAttribute("attribute.mnemosyne.memory_magic_resist",
>                                         1.0D, -100.0D, 100.0D).setSyncable(true));
> ```

> **命名规范必须与 ISS 对齐**：ISS 用的是 `<school>_spell_power` 与 `<school>_magic_resist` 后缀。
> 所以我们用 `memory_spell_power` / `memory_magic_resist`，**不是** `mnemosyne_spell_power`。
> 这样在代码里能和其他学派走同一套逻辑，也便于玩家理解。

### 3.3 必须挂载到玩家

**属性注册完不会自动生效。** 必须监听 `EntityAttributeModificationEvent`，把属性加到玩家（以及其他需要它的实体）身上：

```
EntityAttributeModificationEvent:
    如果 event.has(EntityType.PLAYER):
        event.add(EntityType.PLAYER, 记忆法术强度属性)
        event.add(EntityType.PLAYER, 记忆法术抗性属性)
```

**不挂载的后果**：`LivingEntity.getAttribute(attr)` 返回 `null`，任何读取都会 NPE；或者属性值为 0 导致伤害恒为 0。

### 3.4 属性如何影响法术威力

回顾 [01 文档 §5.2](01_ISS官方API参考.md) 的公式：

```
getSpellPower(level, entity)
    = (baseSpellPower + spellPowerPerLevel × (level − 1))
      × SPELL_POWER(实体)
      × 学派强度属性(实体)          ← 我们的 memory_spell_power 在这里
      × POWER_MULTIPLIER
```

学派强度属性通过 `SchoolType.getPowerFor(entity)` 被读取，所以**只要 `SchoolType` 里传的是我们的属性，公式会自动生效**，不需要额外代码。

### 3.5 抗性如何影响伤害

抗性**不会**自动生效——它需要在伤害计算时手动读取并减免。

正确做法：所有记忆法术的伤害都走 `spell.getDamageSource(caster)`（返回 `SpellDamageSource`），ISS 的伤害管线会自动按学派读取 `getResistanceFor(target)` 做减免。

> **这是最容易漏的一步**：如果直接用原版 `DamageSource`，目标的 `memory_magic_resist` 完全不起作用，平衡会崩。

## 四、伤害类型注册

### 4.1 数据包文件

`data/mnemosyne/damage_type/memory.json`（伤害类型 id = `mnemosyne:memory`）

```json
{
  "exhaustion": 0.0,
  "message_id": "mnemosyne_memory",
  "scaling": "when_caused_by_living_non_player"
}
```

> **为什么 `message_id` 不叫 `memory`**：`message_id` 决定死亡消息语言键
> `death.attack.<message_id>`。叫 `memory` 会和别的模组撞键。
> 用 `mnemosyne_memory` 前缀化，唯一且可读。
>
> 格式逐字取自 ISS 的 `data/irons_spellbooks/damage_type/fire_magic.json`
> （`exhaustion: 0.0` + `scaling: "when_caused_by_living_non_player"`）。
> 注意 `exhaustion` 是 0.0 而不是设计稿写的 0.1 —— 法术伤害不该额外消耗饥饿。

### 4.2 死亡消息语言键

| 键 | 内容（英文） |
|---|---|
| `death.attack.mnemosyne_memory` | `%1$s was erased by %2$s's memory magic` |
| `death.attack.mnemosyne_memory.player` | `%1$s was erased by %2$s's memory magic` |

> 对照 ISS：`death.attack.blood_magic = %1$s was killed by %2$s's blood magic`。
> 中文：`%1$s 的记忆被 %2$s 抹去了`。

### 4.3 与 `SchoolType` 的关联

`SchoolType` 构造时传入的 `ResourceKey<DamageType>` 必须指向这个伤害类型，否则 `getDamageSource()` 拿不到正确的类型。

## 五、音效注册

### 5.1 默认施法音效

每个学派需要一个"默认施法音"。ISS 的做法是为每个学派注册一个音效事件，然后在 `SchoolType` 里引用。

| 事件 id | Java 常量 | 用途 |
|---|---|---|
| `mnemosyne:cast.default` | `ModSounds.CAST_DEFAULT` | 学派默认施法音（所有记忆法术的兜底施法音） |

在 `assets/mnemosyne/sounds.json` 里声明（**已定稿，不要改**）：

```json
"cast.default": {
  "subtitle": "subtitles.mnemosyne.cast",
  "sounds": [
    { "name": "irons_spellbooks:generic/ender_cast", "volume": 0.85, "pitch": 0.95 }
  ]
}
```

> **⚠️ 更正（v2.3 起）**：本文早期版本写的是
> "音频文件放在 `assets/mnemosyne/sounds/cast/mnemosyne.ogg`"。
> **那是错的，已作废。** 忆海的策略是**零新增音频**：
> `sounds.json` 的 `sounds` 数组项是**资源路径**，可以跨命名空间引用，
> 所以我们全部指向 `irons_spellbooks:` 下已存在的 ogg。
> 理由（含 ISS `All Rights Reserved` 的授权分析）见 `08_音效方案.md`。
>
> **Java 侧只注册 `SoundEvent`，不碰任何 .ogg 文件。**

### 5.2 法术专属音效（见 [09 美术与音效](../09_美术与音效.md)）

每个法术可以覆写 `getCastStartSound()` / `getCastFinishSound()` 指定自己的音效。共 **23 条** `spell.*` 事件（按 16 个法术，逐条见 `08_音效方案.md` §3.2）。

## 八、注册顺序与依赖

**注册顺序很重要**，因为存在依赖关系：

```
① 属性（ModAttributes）
      ↓ SchoolType 需要引用属性
② 学派（ModSchools）
      ↓ 法术的 DefaultConfig 需要引用学派 id
③ 音效（ModSounds）
      ↓ SchoolType 需要引用音效
④ 伤害类型（数据包，自动加载）
      ↓ SchoolType 需要引用伤害类型
⑤ 法术（ModSpells）
      ↓ 依赖学派 id
⑥ 物品 / 方块 / 实体 / 效果
```

> **实际实现时**：Forge 的 `DeferredRegister` 会自动处理注册时机，只要所有 `DeferredRegister` 都挂到了模组总线上，注册顺序由 Forge 保证。
> **但要注意**：`SchoolType` 构造时引用的属性 Supplier 必须是**惰性的**（`Supplier<Attribute>` 而不是 `Attribute`），否则在注册阶段属性可能还没就绪。

## 九、验证清单

注册完成后，用以下方式验证：

| 验证项 | 方法 | 期望结果 |
|---|---|---|
| 学派注册成功 | `/irons_spellbooks schools`（若存在该指令）或遍历 `SchoolRegistry.REGISTRY` | 能查到 `mnemosyne:memory` |
| 属性注册成功 | 在游戏里查看玩家属性（如 `/attribute @s mnemosyne:memory_spell_power get`） | 返回 1.0（默认值） |
| 焦点标签生效 | `SchoolRegistry.getSchoolFromFocus(new ItemStack(忆晶))` | 返回记忆学派 |
| 伤害类型生效 | 用记忆法术击杀生物 | 死亡消息显示 "was erased by ... memory magic" |
| 学派强度生效 | 给玩家加 `memory_spell_power` 后施法 | 伤害按比例提升 |
| 学派抗性生效 | 给目标加 `memory_magic_resist` 后施法 | 伤害按比例降低 |
