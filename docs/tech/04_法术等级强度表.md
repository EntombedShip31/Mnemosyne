## 〇、两条必须先读的更正

在写数值之前，必须先更正此前设计文档中的两处**与官方实现不符**的地方：

### 更正 1：ISS **没有** CHARGE（蓄能）施法类型

`CastType` 只有四个值：`NONE` / `INSTANT` / `LONG` / `CONTINUOUS`。

| 之前写的 | 实际应该是 |
|---|---|
| 记忆掠夺：蓄能（Charge） | **LONG**，`castTime = 40` tick |
| 忆海：蓄能（Charge） | **LONG**，`castTime = 60` tick |
| 千忆归一：蓄能（Charge） | **LONG**，`castTime = 50` tick |
| 写入三件套：瞬发 | **LONG**，`castTime = 8~16` tick（有起手动作） |

> "蓄能越久越强"若要保留，用 `LONG` + 覆写 `onServerCastTick(...)` 逐 tick 累加实现（详见 [03 文档 §二](03_法术实现规范.md)）。

### 更正 2：`INSTANT` 类型会强制 `castTime = 0`

官方实现：

```
getCastTime(level) = 0  若 getCastType() == INSTANT
                   = castTime  否则
```

所以**只要声明了 INSTANT，`castTime` 字段就完全失效**。想让法术有起手时间，**必须用 LONG**。

### 更正 3：冷却不随等级变化

`getSpellCooldown()` 没有参数，**冷却是一个固定值**（`cooldownInSeconds × 20` tick）。

因此本文所有法术的冷却都是**固定值**，等级收益全部体现在效果上。

## 一、稀有度与等级的对应关系

本流派**统一 `maxLevel = 5`**。理由：在默认稀有度权重 `[0.3, 0.25, 0.2, 0.15, 0.1]` 下，
`minRarity = COMMON` 的 5 级法术，其 5 个等级**恰好一一对应 5 档稀有度**。

各 `minRarity` 下的等级 → 稀有度映射（**反编译算法推导，非估计**）：

| 等级 | minRarity=COMMON | minRarity=UNCOMMON | minRarity=RARE | minRarity=EPIC | minRarity=LEGENDARY |
|---|---|---|---|---|---|
| **1** | Common | Uncommon | Rare | Epic | Legendary |
| **2** | Uncommon | Rare | Rare | Epic | Legendary |
| **3** | Rare | Rare | Epic | Epic | Legendary |
| **4** | Epic | Epic | Legendary | Legendary | Legendary |
| **5** | Legendary | Legendary | Legendary | Legendary | Legendary |

> **实用含义**：一本 Common 法术的卷轴，1 级时是普通卷轴（能装进最便宜的法术书），
> 5 级时是**传奇卷轴**（需要下界合金法术书）。这就是"法术书有很多等级"的机制本质。

## 二、法力基准

ISS 的**默认最大法力为 100**（`AttributeRegistry.MAX_MANA` 默认值，从 class 常量池提取）。

因此法力消耗的定位：

| 稀有度 | 法力区间 | 占基础法力条比例 |
|---|---|---|
| Common | 10 – 20 | 10% – 20% |
| Uncommon | 20 – 40 | 20% – 40% |
| Rare | 30 – 60 | 30% – 60% |
| Epic | 70 – 100 | 70% – 100%（一整条） |
| Legendary | 120 – 210 | 需装备提升最大法力才能施放 |

### 5. 铭忆 Engrave

~~`encode_spell`（术忆）~~ **已删除（2026-09-18）**，由 `engrave`（铭忆）取代。

> ⚠️ **本节数值曾被写成已删除的「术忆」的**（COMMON / 25 法力 / 5 级）。
> 实际实现是 **LEGENDARY / 100 法力 / `maxLevel = 1`**（`EngraveSpell` 实测，
> 与 `13_数值总表.md` §一 一致，由 `tools/check_spell_numbers.py` 对账）。已订正。

`engrave` · **LEGENDARY** · LONG · 冷却 15.0s · 吟唱 20 tick · 标签：写入 · 容量

| 字段 | 值 |
|---|---|
| `baseManaCost` | **100**（固定） |
| `manaCostPerLevel` | **0** |
| `baseSpellPower` | 1 |
| `spellPowerPerLevel` | 0 |
| `castTime` | **20** |
| `maxLevel` | **1** |

| 等级 | 稀有度 | 法力 | 法术上限 | 临时忆格 |
|---|---|---|---|---|
| 1 | Legendary | 100 | **+2** | **+1** |

- **法术上限 +2**：临时提高装备槽里那本法术书的 `maxSpellCount`，到期自动还原
- **临时忆格 +1**：持续时长 = 忆格记忆有效期（默认 **120 秒**；忆者法袍 4 件套 **180 秒**）
- 仍然走写入类的通用门槛：**必须有一个空忆格**（净收益 = 法术上限 +2 + 临时忆格 1 格）
- 身上没有可铭刻的法术书 → 施法失败
- 与「忆格扩张」的区隔：那个只加临时忆格、有等级门槛；铭忆加的是**法术上限**
- **不需要释放端**（这是它取代术忆的原因 —— 术忆的释放端依赖已被删除的「复诵」）
- `maxLevel = 1` 的理由：容量增益是"开关"不是"曲线"，多给等级会击穿稀缺资源

## 五、强度校验

### 5.1 与官方法术的横向对比

| 对比项 | 官方参照 | 记忆流派 | 结论 |
|---|---|---|---|
| 最高单次伤害 | Fireball（25s 冷却，约 12-20 伤害） | 千忆归一（120s 冷却，最高 200） | 冷却 5 倍，伤害 10 倍——**合理** |
| 常见输出法术 DPS | Firebolt：约 6 伤害 / 1.5s ≈ 4.0 | 忆矢：约 6 伤害 / 1.5s ≈ 4.0 | **持平** |
| 廉价控制 | Slow（减速） | 遗忘（移除 AI 行为） | 记忆的控制更强但更贵 |
| 满级总法力需求 | Fireball Lv5 = 120 | 千忆归一 Lv5 = 210 | 需要装备堆最大法力 |

### 5.2 关键平衡检查

| 检查项 | 结论 |
|---|---|
| 记忆流派是否有最高的 DPS？ | **没有**。忆矢与 Firebolt 持平，其余法术都带前置条件 |
| 千忆归一是否过强？ | 200 伤害需要：120 秒冷却 + 囤满 5 格 + 150-210 法力 + 2.5 秒站桩。**代价足够** |
| 认知崩坏是否过强？ | 60 真实伤害需要先叠满 5-6 层（5-6 次施法）。**前置足够** |
| 痛忆是否可被滥用？ | 上限 80% 最大生命，且需要先挨打 |
| 遗忘是否破坏 Boss 设计？ | BOSS 全部走降级分支（降攻 15% / 停攻 1.5s） |
| 低阶法术在后期是否有用？ | **有**。忆矢是认知崩坏的前置，遗忘是失忆的低配版 |

### 5.3 反作弊检查

| 潜在漏洞 | 防护 |
|---|---|
| 站在岩浆里刷痛忆 | 上限 80% 最大生命 |

## 六、需要覆写官方默认行为的法术

以下 4 个法术**不能**只靠五个数值字段实现，必须覆写方法：

| 法术 | 需要覆写 | 原因 |
|---|---|---|
| 术忆 / 质忆 / 痛忆 | `getCastTime(int level)` | 施法时间需要随等级递减（8→4 tick），官方默认返回固定 `castTime` |
| 术忆 | `checkPreCastConditions(...)` | 无空忆格时中断并提示 |
| 质忆 | `checkPreCastConditions(...)` | 无目标时不消耗法力 |
| 认知崩坏 / 千忆归一 | `getUniqueInfo(int, LivingEntity)` | tooltip 需要显示"当前层数 × 伤害"这类动态信息 |
| 所有遗忘类 | `canBeCastedBy(...)` | 判断目标是否为 BOSS，走不同分支 |

## 七、数据校验清单（填完数值后自查）

| 检查项 | 方法 |
|---|---|
| 法力曲线单调递增 | 检查 `manaCostPerLevel > 0` |
| 威力曲线单调递增 | 检查 `spellPowerPerLevel >= 0` |
| `maxLevel` 与本类 `*_BY_LEVEL` 数组长度一致 | ⚠️ **不再是全流派统一 5**。2026-09-19 起 `maxLevel` 由 `MnemosyneSpell.memoryConfig(rarity, cd, maxLevel)` **逐法术显式传入**（2 参重载已删除），取值见 [13 文档 §一](13_数值总表.md) 各法术表。数组短 → 高等级被钳到最后一档；数组长 → 多出来的档位永远读不到 |
| 稀有度映射正确 | 用 [01 文档 §七](01_ISS官方API参考.md) 的算法手算一遍 |
| `castTime` 仅在 LONG 类型生效 | INSTANT 法术的 `castTime` 一律填 0 |
| 冷却为固定值 | 确认没有依赖"等级降冷却"的逻辑 |
| 所有伤害走 `SpellDamageSource` | 确认没有直接用原版 `DamageSource` |
| 所有数值可在配置中调整 | 对照 [03 文档 §十一](03_法术实现规范.md) 的配置清单 |
