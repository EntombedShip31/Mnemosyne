# 08 · 音效与音乐方案

> 本文件是 `mnemosyne`（忆海 / 记忆·认知流派）技术文档集的第 8 篇。
> **结论：不制作原创音效与音乐，改为引用 ISS 已有的 197 个音效事件。**
> 所有音效路径均从 `irons_spellbooks-1.20.1-3.16.3/assets/irons_spellbooks/sounds.json` **逐字提取并实测校验**。

---

## 〇、一句话结论

**忆海不需要新增任何一个 `.ogg` 文件。**

`src/main/resources/assets/mnemosyne/sounds.json` 里定义了 **39 个忆海音效事件**，
每一个都指向 `irons_spellbooks:` 命名空间下**已经存在**的音频文件。

校验结果（`tools/check_sounds.py` 实测）：

```
ISS 音效事件  : 197
ISS 音频文件  : 265
忆海音效事件  : 39
通过 : 42        失效 : 0
```

**工作量：1 小时（写 JSON + 校验），而不是 2~3 周（作曲 + 录音 + 混音）。**

## 一、为什么能做到（技术原理）

### 1.1 Minecraft 的 `sounds.json` 是资源路径，不是文件名

`sounds.json` 的 `sounds` 数组里，每一项都是一个**资源路径**：

```json
{ "spell.fire_arrow.cast": { "sounds": [ "irons_spellbooks:spell/fire_arrow_cast" ] } }
```

会被解析为：

```
assets/irons_spellbooks/sounds/spell/fire_arrow_cast.ogg
```

**资源管理器是所有模组共享的**（`ResourceManager` 聚合了所有已加载模组的 `assets/`）。
所以从 `mnemosyne` 的 `sounds.json` 里写 `irons_spellbooks:xxx`，是完全标准的做法。

### 1.2 三层结构：事件名 → 音频文件 → 实际播放

```
忆海的代码调用
    SoundEvent = mnemosyne:spell.recall.prepare
        ↓  （在 mnemosyne/sounds.json 里定义）
    sounds: [ "irons_spellbooks:recall_prepare" ]
        ↓  （资源管理器解析）
    assets/irons_spellbooks/sounds/recall_prepare.ogg
        ↓
    实际播放
```

**关键收益**：我们拥有一层**音效间接层**。

将来若有了原创音效，只需把 `sounds.json` 里的那一行换成 `mnemosyne:xxx`，
**调用方代码一行都不用改**。

## 二、为什么不该自己造音效

### 2.1 授权问题（决定性）

实测 ISS 的 `META-INF/mods.toml`：

```toml
license = "All Rights Reserved"
authors = "Iron431, Lab3"
```

**`All Rights Reserved`** —— 这意味着：

| 做法 | 合法性 |
|---|---|
| 把 ISS 的 `.ogg` **复制**进我们的 jar | ⚠️ **有授权风险**（再分发了他人的版权音频） |
| 从我们的 `sounds.json` **引用** ISS 的音频路径 | ✅ 正常使用依赖的公开资源，属于模组间标准互操作 |
| 引用**原版 Minecraft** 的音效 | ✅ 同上 |

**这条规则不只适用于音效**，也适用于贴图、模型、结构 NBT（见 `09_美术资源管线.md` 的同类讨论）。

### 2.2 工作量与收益不成比例

| 方案 | 工作量 | 质量 | 评价 |
|---|---|---|---|
| **A. 引用 ISS 现有音效** | **1 小时** | 高（专业录制的素材） | ✅ **采纳** |
| B. 程序化生成（Python 合成） | 2~3 天 | 低（合成音一听就假） | ❌ 见 §2.3 |
| C. 外部 CC0 音效库（freesound 等） | 2~3 天 | 中（要逐个试听/裁剪/转码） | ⚠️ 备选 |
| D. 原创作曲 + 录音 | 2~3 周 | 最高 | ❌ 性价比极低 |

**记忆流派的核心价值在"信息与控制"，不在视听表现。** 把 2~3 周投在音效上，
不如投在"临时遗忘"这个最大技术难点上（见 `03_法术实现规范.md` §遗忘）。

### 2.3 为什么程序化生成不可行（实测）

我实际验证了本机的工具链：

| 工具 | 状态 |
|---|---|
| `ffmpeg` | ❌ 未安装 |
| `soundfile`（libsndfile，可写 OGG Vorbis） | ❌ 安装被中断 |
| `numpy` / `scipy` | ❌ 未安装 |
| Python 标准库 `wave` | ✅ 可用（**但只能写 WAV**） |

**致命问题：Minecraft 只加载 `.ogg`（Ogg Vorbis），不加载 `.wav`。**

要用 `wave` 生成 WAV 再转 OGG，就必须有 Vorbis 编码器（ffmpeg / libsndfile / oggenc）。
本机三者皆无，纯 Python 手写 Vorbis 编码器不现实。

**即使能编码，音质也不够**：法术音效需要的是"有质感的魔法声"（金属共鸣、低频轰鸣、颗粒噪声的复杂叠加），
程序化合成出来的通常是"电子蜂鸣"，一听就出戏。

**结论：程序化生成在技术上不可行，在质量上不达标，双重否决。**

## 四、实现要点

### 4.1 代码里怎么引用

**不要**去 `ForgeRegistries.SOUND_EVENTS` 里查 ISS 的事件名（那样会和 ISS 的内部命名耦合）。
**应该**注册我们自己的 `SoundEvent`（用 `DeferredRegister`），然后到处用我们的。

```java
public final class ModSounds {
    public static final DeferredRegister<SoundEvent> SOUNDS =
            DeferredRegister.create(ForgeRegistries.SOUND_EVENTS, MnemosyneMod.MODID);

    public static final RegistryObject<SoundEvent> CAST_DEFAULT =
            register("cast.default");
    public static final RegistryObject<SoundEvent> SPELL_RECITE =
            register("spell.recite.cast");
    // ... 其余 37 个

    /** ISS 的 SchoolType 需要 Supplier<SoundEvent>，直接用 RegistryObject 即可 */
    public static final RegistryObject<SoundEvent> MEMORY_CAST = CAST_DEFAULT;

    private static RegistryObject<SoundEvent> register(String name) {
        return SOUNDS.register(name, () -> SoundEvent.createVariableRangeEvent(
                ResourceLocation.fromNamespaceAndPath(MnemosyneMod.MODID, name)));
    }
}
```

**⚠️ 注意事件名里的点号**：`spell.recite.cast` 作为 `ResourceLocation` 的 path 是合法的
（path 允许 `.` `_` `-`）。ISS 自己也大量这么用（`spell.recall.prepare`）。

### 4.2 播放

```java
// 服务端播放（推荐：让所有附近玩家都听到）
level.playSound(null, entity.getX(), entity.getY(), entity.getZ(),
        ModSounds.SPELL_RECITE.get(), SoundSource.PLAYERS, 1.0F, 1.0F);

// 只给一个玩家播放（HUD 反馈）
player.connection.send(new ClientboundSoundPacket(
        Holder.direct(ModSounds.HUD_ENGRAM_DECAY.get()),
        SoundSource.MASTER, player.getX(), player.getY(), player.getZ(),
        0.4F, 1.3F, level.getRandom().nextLong()));
```

### 4.3 字幕（subtitle）

`sounds.json` 里的 `"subtitle"` 指向 lang 键，需要在 `assets/mnemosyne/lang/*.json` 里定义：

```json
"subtitles.mnemosyne.cast": "记忆在流动",
"subtitles.mnemosyne.spell.recite": "复诵",
"subtitles.mnemosyne.hud.engram_decay": "记忆正在消散"
```

**建议给所有 39 个事件都配字幕** —— 这是无障碍设计，也让玩家能通过字幕理解战斗节奏。

### 4.4 ⚠️ 校验流程（升级 ISS 后必做）

```bash
cd tools
python check_sounds.py            # 自动定位 ISS，校验全部 42 条引用
python check_sounds.py --verbose  # 列出每一条
```

**什么时候跑**：
- 每次升级 ISS 版本后（**必做**）
- 修改 `sounds.json` 后
- 发布前

**失效的表现**：不会崩溃，只是**静音**（Minecraft 找不到音频文件时只记一条 warn 日志）。
所以**必须靠脚本校验**，不能靠肉眼。

### 4.5 ⚠️⚠️ `sounds.json` 里**绝对不能写注释键**（实测，2026-09-16）

**这是本项目踩过最隐蔽的一个坑：一个 `_comment` 键会让整份 `sounds.json` 被丢弃，
39 个音效事件全部不注册 —— 而日志里只有一条 warn，`./gradlew build` 完全不报。**

实测证据（反编译 `client.jar` 的官方映射源码）：

```java
// net.minecraft.client.sounds.SoundManager#prepare
try {
    Map<String, SoundEventRegistration> map =
        GsonHelper.convertToMap(f_120346_, reader, f_120347_);   // ← 整份文件在这里一次性反序列化
    for (Map.Entry<String, SoundEventRegistration> entry : map.entrySet()) {
        soundmanager$preparations.m_246105_(new ResourceLocation(s, entry.getKey()), entry.getValue());
    }
} catch (RuntimeException runtimeexception) {
    f_120345_.warn("Invalid {} in resourcepack: '{}'", "sounds.json", resource.m_215506_(), runtimeexception);
}
```

```java
// net.minecraft.client.resources.sounds.SoundEventRegistrationSerializer#deserialize
JsonObject jsonobject = GsonHelper.m_13918_(p_119827_, "entry");   // = convertToJsonObject
// net.minecraft.util.GsonHelper#m_13918_
if (!p_13919_.isJsonObject()) {
    throw new JsonSyntaxException("Expected " + p_13920_ + " to be a JsonObject, was " + ...);
}
```

**推演链**：`_comment` 的值是 JSON **数组** → `convertToJsonObject` 抛 `JsonSyntaxException`
→ 它是 `RuntimeException`，被 `SoundManager` 的 `catch` 吞掉 → **`map` 从未被赋值**，
那个 `for` 循环一次都不执行 → 该命名空间**零个**音效事件注册。

两个反直觉点：
1. **不是"跳过这一条"** —— Gson 是整份文件一次性解析，一条非法就全盘皆输。
2. **只记 warn，不记 error**，而且只在客户端资源重载时打印一次。查日志都未必看得见。

**替代做法**：把说明文字放本文档（就是你正在读的这段），**不要**放进 `sounds.json`。
JSON 没有注释语法，任何"拿键当注释"的写法都会破坏 schema。

**自动防线**：`tools/check_resources.py` 会断言 `sounds.json` 的**每个顶层键都是对象**。

```bash
python tools/check_resources.py
```

## 五、如果要换原创音效（升级路径）

因为有了音效间接层，替换成本极低：

```
1. 把原创 .ogg 放到 src/main/resources/assets/mnemosyne/sounds/<path>.ogg
2. 在 sounds.json 里把该事件的 sounds 数组从
      [ { "name": "irons_spellbooks:recall_prepare", "pitch": 1.0 } ]
   改成
      [ "mnemosyne:spell/recite" ]
3. 跑 python tools/check_sounds.py 确认（会从"通过"变成"待自制"，正常）
4. 代码零改动
```

**建议的替换优先级**（如果要投入美术预算，按这个顺序）：

| 优先级 | 事件 | 理由 |
|---|---|---|
| 1 | `cast.default` | 玩家听到次数最多，收益最高 |
| 2 | `spell.thousand_memories.*` | Legendary 法术，值得专属音效 |
| 3 | `spell.sea_of_memory.*` | 同上 |
| 4 | `hud.engram.*` | 高频 HUD 反馈 |
| 5 | 其余 | 低优先级 |

### 外部 CC0 音效库（备选方案 C 的具体做法）

如果要走这条路：

| 站点 | 授权 | 说明 |
|---|---|---|
| freesound.org | 混合（**必须筛 CC0**） | 最大的免费音效库 |
| opengameart.org | CC0 / CC-BY | 游戏音效为主 |
| Pixabay Sounds | 类 CC0 | 无需署名 |

**流程**：下载 WAV → 用 Audacity 裁剪/淡入淡出 → 导出 OGG Vorbis（质量 5~6）→ 放入 assets。

**注意**：Minecraft 只接受 **单声道或立体声、Vorbis 编码、文件名全小写**的 ogg。
用 ffmpeg 批量转换：

```bash
ffmpeg -i in.wav -c:a libvorbis -q:a 5 -ac 1 out.ogg
```
